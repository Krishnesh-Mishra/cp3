# CP3 v0.2.0 — TypeScript compatibility

- Version: `0.2.0` (`version.txt`)
- Theme: ordinary TypeScript class and error-code should work in CP3, on the
  way to native executables with no hidden runtime machinery
- Release status (2026-11-09): the full corpus passes on **both** reference
  platforms — Windows (3140 found, 3117 passed, 0 failed, 23 ambiguous) and
  Linux via WSL (3140 found, 3117 passed, 0 failed, 23 ambiguous), built from
  the post-literal-default compiler. arm64 package outputs are marked
  `-untested`. Release packaging (Windows MSI via WiX, Linux tarball) is
  documented in [`docs/BUILD.md`](../BUILD.md); the tag is cut from
  `version.txt`.
- Scope ledger: [`ROADMAP.md`](../../ROADMAP.md) (§v0.2.0, marked Done);
  design notes under `docs/design/`

CP3 v0.2 is a compiler and standard-library wave. There is no runtime feature
flag to turn on: rebuilding your application with the v0.2 compiler is enough
for the source-level changes to take effect.

186 commits landed between `v0.1.0` and `v0.2.0`. The headline themes were the
TypeScript-compatibility surface (type-system cleanup, classes, errors,
promises), native-grade standard library breadth (networking/TLS, collections,
Date, exact integer widths), packaging for multiple platforms, and a corpus
that grew from 2115 cases to 3140.

## What shipped

### `std/json` — the file-oriented API and inline `<T>` parsing

`JSON` (imported as `import JSON from "std/json"`) gains five members,
alongside `JSON.parse<T>` / `JSON.stringify`:

| Call | Result | Behavior |
| --- | --- | --- |
| `JSON.parseFileSync<T>(path)` | `T` | Reads and parses like `JSON.parse<T>` on the file's text |
| `JSON.parseFile<T>(path)` | `Promise<T>` | Same, on the async fs path |
| `JSON.stringifyToFileSync(path, value)` | `void` | Serializes and **overwrites** `path` (raw write, no append) |
| `JSON.stringifyToFile(path, value)` | `Promise<void>` | Same, async |
| `JSON.verify<T>(text)` | `boolean` | Same checks as `JSON.parse<T>`, never throws |

- `<T>` is **required** on `parse`, `parseFileSync`, `parseFile` and
  `verify`; a bare call is a compile error (`CP3208`). The stringify family
  (`stringifyToFile(Sync)`) takes **no** type argument — the value's own
  type is all the serializer needs.
- `T` may be a primitive, a primitive array, a registered plain-record
  interface, or an inline object annotation (`JSON.parse<{ x: number }>(text)`);
  inline object shapes lower through the same record engine, including nested
  plain records and `?:` members (absent-with-no-error).
- Every failure of the parse/verify surface throws (parse side) or rejects
  (async side) with the same `json::ParseError` class `JSON.parse<T>` uses;
  an `fs` read error is boxed into it. `verify<T>` never throws: it returns
  `false` for malformed JSON, a duplicate key anywhere in the text, a
  missing/mistyped required field, or a shape mismatch. Extra keys are
  ignored; keys match case-sensitively.
- `stringify(value, replacer?, space?)` shipped earlier in the 0.2 line: an
  ECMAScript replacer callback `(key, value) => replacement` (returning
  `undefined` omits a property), a `string[]` allowlist, `space` as
  `number | string`, with a legacy numeric second argument still accepted as
  indent.
- Parsing is backed by an embedded amalgamated simdjson v5.1.1 build — no
  system JSON dependency.

Fixture family: `tests/cases/stdlib/02/json/file/`. See
[`docs/content/03-standard-library/09-json.md`](../content/03-standard-library/09-json.md).

### Networking, HTTP, TLS and WebSocket

- **Native fetch over HTTPS.** `fetch` rides the shared OpenSSL engine in
  this release; earlier v0.1 had HTTP only.
- **TLS server support.** `createServer` and `WebSocketServer` serve TLS via
  uWS `SSLApp` (certificate/key as PEM file paths). The client side of
  `fetch` and `WebSocket` (`wss://`) works over the same engine.
- **`tls({...})` factory.** Reusable TLS options objects for server TLS; peer
  certificates verify against an embedded Mozilla CA bundle (118 certificates,
  SHA-256 `427c064216761a1e…`, embedded at compile time — no runtime file
  lookup and no source-tree dependency; packaged as
  `share/openssl/cacert.pem` as well) with `SSL_CERT_FILE` override.
  linux-arm64 now selects the OpenSSL-linked native row and compiles TLS
  code paths; windows-arm64's archive is vendored but the arm64 outputs are
  **not tested** in this release.
- **`peerCertificate`** on the TLS path fills subject DN, issuer DN, serial
  number, SHA fingerprints and validity dates.
- **`dns.lookup`** (`dns.lookup(hostname[, options][, callback])`-style) is
  now typed and wired end to end: `dns.lookup` and the `dns.lookup` namespace
  member both resolve, lowered to a libuv-backed `dnsResolve(host)` runtime.
  Verified host resolution feeds tcp/udp/tls/dns raw-socket integration.
- **HTTP server helpers**: `res.redirect`, `res.sendFile`, `res.cookie`,
  `req.cookies`, `req.ip`, `req.protocol`, direct `headerValue` lookup,
  static-middleware path joining, and the `render` fallback. Cookie
  `maxAge` is interpreted in seconds (was previously mismatched).
- **Raw sockets**: `dns.lookup` is wired end to end (`native` row, sema
  `lookup` member, codegen lowering, corpus cases). The `tcp` / `udp` /
  `tls` raw-socket C++ **is built into the `std/network` native package** but
  the cp3-source-visible API (`createTcpServer`, `connectTcp`,
  `createUdpSocket`, `connectTls`, `TlsServer`, …) is **not exported** in
  this version: the `networkMember`/named-import tables and the codegen
  lowering were never wired up (the agent output exists as unapplied paste
  fragments under `src/std/network/{tcp,udp,tls}/`). TLS servers today means
  `createServer({ tls })` / `WebSocketServer({ tls })`; the docs state the
  same limitation under "Raw sockets (TCP, UDP, TLS)". Wiring the raw API is
  an open item.

See [`docs/content/03-standard-library/13-network.md`](../content/03-standard-library/13-network.md).

### TLS certificate trust

This release ships a fully vendored OpenSSL 3.5.5 — one pinned source
(`openssl-3.5.5` tag, commit `67b5686b4419b4cb8caa502711c41815f5279751`) —
rather than relying on a system OpenSSL: windows-x64 was built from that
pinned tree in MSYS2 UCRT (2026-11-07), linux-x64 from the same tree under
WSL2 (GCC 15.2.0), and both arm64 targets were built 2026-11-08 (aarch64
cross-GCC; llvm-mingw for windows-arm64). The superseded windows
`openssl-3.5.4-1` package checksums are retained in
`ossl-3.5.4-package.sha256` for the audit trail. An embedded Mozilla CA
bundle (`vendor/third_party/openssl/cacert.pem`, 118 certificates, SHA-256
`427c064216761a1e72a8b30f0d954d08cb6e4435a82091fb865afd20c8497285`) makes
HTTPS work out of the box with no `SSL_CERT_FILE` setup; `SSL_CERT_FILE`
remains honored for enterprise roots. The uSockets archives were rebuilt
`WITH_OPENSSL=1` for all four targets (TLS-capable).

### Standard library breadth

- **`std/collections`**: `Queue`, `Stack`, `PriorityQueue`, `RingBuffer`,
  `BitSet`, `MultiMap`, `ConcurrentMap` (with a hash-seed bucket; counts and
  capacities are exact `usize`), plus collection constructors that accept an
  iterable (`new Map(entries)`, `new Set(iterable)`), `Set` algebra,
  `[...set]` / `[...map]` spread, `Map.groupBy`, `Object.fromEntries`,
  `Record<string, V>` index read/write, a `BitSet` handle fix, and
  `LRUCache<K, V>` with bounded capacity and MRU eviction. Statically-cached
  collections lower to hash-seeded buckets, so lookups do not degrade at
  small sizes.
- **`std/object`**: `Object.assign`, `Object.is`, `Object.freeze` (with a
  freeze registry the linearizer understands), and
  `Object.preventExtensions` semantics pinned to JS (`isSealed` stays true
  after `preventExtensions`).
- **`std/math`**: inverse trigonometric and hyperbolic functions, `exp`,
  `log1p`, `hypot`, `sign`, and constants; argument-driven native result
  narrowing (integral/f32 arguments keep native widths; `number` stays
  `number`); `cbrt` snaps to nearest-integer roots (LLVM's expansion is an
  ulp off exact cubes).
- **`std/number`** (language-level): `Number` methods/statics/constants,
  `Number.isSafeInteger`, `toString(radix)`, `parseInt`/`parseFloat`, coercion
  globals `Number`/`Boolean`/`isNaN`/`isFinite`, and scalar `toString` +
  `String.fromCharCode` lowerings; `wrappingMul` for exact unsigned
  arithmetic.
- **`std/date`**: `getTime`, `getDay`, UTC getters and setters, `Date.parse`;
  exact `i64` timestamp widths (under `rust`/`cpp`).
- **`std/process`**: `cwd`, `chdir`, `pid`, `ppid`, `uptime`, `memoryUsage`,
  `hrtime`, `exitCode`, `platform`, `arch`, `version`, `stdout`/`stderr`
  write streams; `process.nextTick`, `queueMicrotask`, `setImmediate`.
- **`std/os`**: `totalmem`, `freemem`, `loadavg`, `networkInterfaces` (libuv);
  exact `u64` memory widths.
- **`std/fs`**: exact `u64` file-size width and `fs` integer-width fixes;
  the `install-dir` install location shipped with the packaging wave.
- **`std/url`**: URI encode/decode helpers (`encodeURI` family) plus URL
  extensions documented in `24-url-extensions.md`.
- **`std/io`**: file-descriptor readiness and a `poll` helper.
- **`std/text`** *(new module)*: `TextEncoder` / `TextDecoder` with WHATWG
  semantics.
- **`std/time`** *(new module)*: `time.stopwatch()` and `console.time`,
  `console.timeEnd` (with real indented output).
- **`std/hash`** *(new module)*: xxHash-64 checksums (`xxhash64` design
  doc; the xxHash archive is vendored and packaged).
- **`std/readline`** *(new module)*: `readLine()` / `readLines()` promises
  over stdin plus `on("line" | "close", ...)` events.
- **`std/console`**: `dir`, `trace`, `count` / `countReset`,
  `group` / `groupEnd` (real indent), `table`.
- **`std/crypto` / `std/buffer`**: API extensions in the integer-width wave
  (exact widths, `wrappingMul`, `fromCharCode`).
- **`structuredClone(value)`** deep-copies any supported value, reusing the
  worker cloner; it is a global, no import required.
- **`atob` / `btoa`** globals (base64); `atob` throws a catchable error on
  invalid input.
- **`String.prototype.replace` / `replaceAll`** accept a `RegExp` argument
  (literal replacement, not JS `$&` substitution patterns).
- **Exact std integer widths, native-first**: one semantic-width table
  (`cp3/host/std_integer.hpp`) pins HTTP ports/status to `u16`, pids/exit
  codes to `i32`, timestamps to `i64`, sizes/counts to `u64`/`usize`. Rust/
  C++ projects get the width; `typescript` keeps `number`. Checked arithmetic
  where the width demands it; exact literal lexing (`0x…`, `0b…`, `_`
  separators, bounds for `i64`/`u64`), and exact `parseTo<T>` conversion.
  `Math` natively narrows results by argument width (see `std/math`).
- **`parseTo(text, Type)` / `parseTo<Type>(text)`**: bidirectional scalar
  conversion between `string` / `number` / `boolean` / native widths, at
  compile time where the types are known.
- **Arrays**: `splice`, `concat`, `reverse`, `reduceRight`, `lastIndexOf`,
  `keys`, `values`, `entries()` (yields `[index, value]` pairs),
  `Array.isArray` as a compile-time constant, `toSpliced`, `with`,
  `copyWithin`, `flat(depth)`; modern `map`/`filter`/`reduce`-family methods
  with JS callback `this`-context binding.

### Type system and classes

- **Polarity narrowing** for `||`, `??`, `?.` and `while` conditions, plus
  optional-chaining codegen (`?.` chains short-circuit instead of evaluating).
- **Nullable class references**: non-null assertion (`x!`), `as` casts,
  definite assignment (`x!: T` on class fields), and narrowing on
  `if (x != null)` — closing the nullable-class-types ledger item.
- **Enums are TypeScript-parity**: number-backed enum arithmetic, relationals,
  and cross-enum arithmetic between number-backed enums; `enum → number`
  assignment; enum boundaries normalize; enum optional members format
  correctly. String-backed enums keep their rejections.
- **`readonly T[]` / `readonly [A, B]`** qualifiers on array/tuple
  annotations (read-through, zero runtime cost).
- **`Array<number>(n)`**: the explicit type argument on the array family
  constructor is accepted.
- **Optional class fields** (`x?: T`): lower to `std::optional<T>` and read as
  `T | undefined` with statically visible types.
- **Class members**: parameter properties, `static` initialization blocks,
  zero-overhead `instanceof`, super-constructor call validation, TS member
  syntax support (modifiers, `#` private fields and methods, parameter
  properties), and virtual dispatch (see below).
- **Typed array family**: `std/typed-arrays` lanes and `Array<number>(n)`
  land with the number rows.
- **Fresh-literal `Object.assign` merge semantics** (JS key order, later
  sources win); reused-binding targets keep their fixed shape.
- **`readonly` patterns and empty-pattern defaults**: empty array literals
  with pattern defaults destructure; the rest arm clamps instead of reading
  out of bounds.

### Virtual dispatch for overriding methods

A method that has an override **anywhere in the program** now lowers to a C++
`virtual` member; a method with no override anywhere stays a direct
(static-bound) call. Analysis is program-wide (all units of a program, before
any unit is emitted) and fails closed:

- an unmodelable base (`extends expr`, a non-named base type, an unresolvable
  base name, or a base cycle) marks **every** non-static, non-private method
  of the class `virtual`;
- duplicate class names widen the analysis to every candidate base (overmark,
  safe direction);
- abstract members in the set are emitted as pure virtual (`= 0`), so vtables
  never reference an undefined symbol;
- static members, `private` members and `#private` members, constructors,
  accessors, and fields are never `virtual`.

`super.method()` remains a base-qualified direct call. Dispatch flows through
`Ref<Base>` and interface thunks as usual. Fixture family:
`tests/cases/classes/01/virtual_dispatch/`,
`tests/cases/classes/01/opt_guard/e_devirtualize_006`…`009`, `e_abstract_044`.

### Enum arithmetic numericness (TS parity)

Number-backed enums read as numbers in arithmetic
(`+ - * / % ** & | ^ << >> >>>`) and in relational operators; any pair of
number-backed enums (same or distinct types) participates, and a number-backed
enum is assignable to `number`. The result type of arithmetic is `number`.
String-backed enums keep their rejections (`CP3411` / `CP3406`); `number` →
enum stays `CP3401`. This supersedes the earlier "distinct enums stay an
error" reading that the enum lanes reported against `j_enum_015`.

### Async and promises

- A class method declared `async` lowers to a coroutine body on the one event
  loop (`async` is not threads).
- `new Promise<T>(executor)` is implemented: the executor runs synchronously,
  `resolve` is typed `(value: T) => void` (nullary for `Promise<void>`), and
  `reject` is typed `(reason: Error) => void` — rejection reasons are
  `Error`-typed, matching the only-`Error` throw law and the runtime resolver
  ABI.
- Promise combinators (`all`, `race`, `allSettled`, **`any`**) treat plain
  values as already-resolved promises (JS parity), including mixed literals
  (`[1, Promise.resolve(2), 3]`), wrapped per element. A mixed non-literal
  source is rejected with a clear diagnostic. `Promise.withResolvers()` and
  `Promise<void>` await are supported.
- `.then`, `.catch` and `.finally` handlers are typed functions: `.then`
  handler receives the promise's value type (nullary for `Promise<void>`),
  `.catch` receives the rejection as `any`, `.finally`'s handler is nullary.
- `Promise.catch` handles `undefined` rejections; network `onError` rejects
  with a wrapped `Error`.

### Memory and cycles

- **Cycle capability analysis, stage 0–1**: class graphs are analyzed for
  back-edges; a diagnostic fires for unbroken strong cycles in an owning
  position. `--report` (on `cp3 check` / `cp3 build`) prints the cycle
  decisions the analysis would make, without changing ownership semantics.
- **Weak escape hatch restored**: `weak` fields break ownership cycles; the
  semantics ship with the escape-analysis pass (see
  [reference cycles](../content/02-runtime/09-reference-cycles-and-weak-links.md)).
- **Fuzzer**: `tools/fuzz_graphs.py` generates adversarial object graphs to
  exercise the cycle analysis against the corpus corpus. Heap-use-after-free
  and stack-use-after-return classes were fixed in the entries-loop and
  worker paths (see “What was fixed”).

### Parallel call diagnostics

`parallel.for`, `parallel.reduce` and `parallel.run` calls are now checked in
the front end instead of failing late (or never):

- an unknown member (`parallel.wait`, `parallel.spawn`, …) is a
  member-not-found diagnostic;
- arity mismatches (`parallel.for` takes a range and a closure; `reduce` takes
  a range, an initializer and a closure);
- the first argument of `for`/`reduce` must be a range;
- the closure parameter count is checked (`for`: 1; `reduce`: 2), and
  `parallel.run` arguments must all be closures; `parallel.reduce` checks the
  closure body shape (typed closure checks).

### Annotations, readonly and constructors

- `readonly T[]` and `readonly [A, B]` qualifiers are accepted on
  array/tuple type annotations. Read-through only; no runtime cost.
- `Array<number>(n)` — the explicit type argument on the array family
  constructor is accepted (previously rejected; pinned by `j_ta_003`).
- Optional class fields (`x?: T`) spell as `std::optional<T>` struct members
  and read as `T | undefined`.
- **Literal default bindings**: see below.
- **Un-annotated literal bindings take the `typeSystem` native default**
  Under `typeSystem: "cpp"` or `"rust"`, an un-annotated binding whose
  initializer is a plain integer literal (`const port = 8080;`, `const a = -5;`)
  now infers a native integer instead of `number`: `i32` when it fits (C++ `int`
  and Rust `i32` share the canonical id), escalating to `i64` and then `u64`;
  literals beyond `u64` keep `number`. Fractional and exponent spellings
  (`2.5`, `2.0`, `1e3`) keep `number` (f64/`double` is the float default, which
  is `number` here). Negative literals are included (`-5` is an `i32`). TypeScript
  projects are unchanged. `parseInt`/`parseFloat` remain legacy
  JS-compatibility globals and always return `number`; use `parseTo<T>` for
  exact native widths. As before, a join that contains `number` absorbs the
  literal (`const port = cond ? parseInt(s) : 8080; // number`) — the default
  applies when the initializer is a bare literal. Fixture family:
  `tests/cases/types/02/native_project_cpp/literal_default/` and
  `tests/cases/types/03/native_project_rust/literal_default/`. See
  [`02-types.md`](../content/01-language/01-variables-and-bindings/02-types.md).

### Packages, modules and `cp3pak`

- **Exported types are independent of the consumer's `typeSystem`** (Rule 3):
  a package built under one mode exports the same structural surface to a
  consumer under any mode. `Rule3` is enforced at package read time; violation
  is a hard error, not a warning.
- **`cp3pak` archives embed native bindings**: installing a package that
  ships native code installs its `.node`-equivalent bundles and rewrites the
  archive surface so linker rows resolve; the installer links the installed
  package implementations instead of the source-tree ones.
- **Package imports resolve and exported types propagate**: importing a
  symbol from a package now types its payload (including generics) instead of
  falling back to `any`/`unknown`.
- **std surface repair**: standard-library surface imports were repaired so
  `import` binds resolve from every entry path; console docs are in sync with
  the emitted surface.

### Toolchain, build and packaging

- **Repository restructure**: `vendor/{third_party,tools}`,
  `dist/{extensions,packaging}`, all build trees under `build/<name>`,
  `out` moved to `build/out`, documentation under `docs/site`, an embedded
  docs virtualenv under `docs/.venv-docs`; every reference rewritten
  (native rows, CMake, packaging, CI, docs).
- **Slim-LTO elimination**: the vendored linux-x64 `libuSockets.a` carried a
  slim-LTO `sni_tree.o` (`.text == 0`) that GNU ld refused to link against
  with GCC 15; the archive was rebuilt from pinned sources with `-flto`
  stripped (`WITH_LTO=0`), `build-linux.sh` now defaults to `WITH_LTO=0`, and
  the MANIFEST pins the recipe.
- **Duplicate runtime TUs**: runtime translation units named by multiple
  native rows were emitted twice; strict linkers (GNU ld) rejected the
  program. Rows are inserted exactly once.
- **Object-format sniffing**: cached objects from another format
  (COFF/ELF/Mach-O/wasm) are rejected and rebuilt instead of being linked.
- **sysroot probe**: requires resolving `__local_stdio_printf_options`
  (`corecrt_stdio_config.h`) at link time; stale sysroots fall back to an
  explicit `--sysroot` instead of reporting ready-but-broken. Clang's MinGW
  `--gcc-toolchain` flag is no longer used.
- **Link stamps cover vendored archives**: a swapped `-l<name>` archive now
  forces a relink.
- **arm64 outputs marked `-untested`** (file name, manifest, `UNTESTED.txt`
  in the staged tree). Vendored arm64 archives (openssl, xxhash, simdutf,
  pcre2, libsodium, libuv, uWebSockets) landed with SHA-256 provenance, but
  nothing has been run on arm64 hardware. The Windows arm64 stage drops the
  MinGW-UCRT-incompatible vendored libs and records an unverified compiler
  version.
- **Multi-platform package flow**: `build-matrix` drives per-target package
  flows; a prerequisite checker validates hosts before packaging; the Windows
  MSI was improved for same-version updates and per-user install; the Linux
  packager prefers the version-matched `.vsix`.
- **Vendored dependencies** (all pinned, all SHA-256-verified): unordered_dense,
  fast_float, moodycamel, XXHash, simdutf, pcre2 (x64 archives added), OpenSSL
  (see above), libuv, uWebSockets, libsodium.

## What changed behaviorally

- **`Object.assign` with a fresh literal target**: the result is the merged
  shape (JS key order, later sources win), not the target's declared shape.
  Code that printed or enumerated the result can observe the new key set and
  order. Reused-binding targets are unchanged in shape; only the rejection of
  source keys not on the target is enforced (see the merge rules under
  "Fresh-literal `Object.assign` merge semantics" above). A reused binding
  passed as a source that carries keys not on the target is now rejected with
  the spread-form diagnostic (`CP3401`), not silently widened.
- **Enums**: number-backed enum arithmetic, relationals and enum → `number`
  assignment that previously failed to compile now compile. Code that relied
  on the diagnostics (`CP3411`/`CP3406`/`CP3401`) at those sites will compile.
- **`parallel.*`**: malformed calls are now front-end diagnostics, reported

## Known limitations and deviations

- `Record<string, V>` canonicalizes to `Map<string, V>`. The runtime
  collection view (Map/Set/`ReadonlyMap`/`Record` forms) is **mutable** at
  runtime; cp3 enforces its fixed shapes at compile time and does not layer a
  runtime immutability contract on the view types.
- **No tracing GC.** Lifetime is reference counting. Strong-reference cycles
  keep objects alive; use a `weak` field to break an ownership cycle. The
  compiler-injected automatic cycle handling (ROADMAP stages 2–3) is not
  enabled; weak links are manual, and their semantics are documented in
  [`docs/content/02-runtime/09-reference-cycles-and-weak-links.md`](../content/02-runtime/09-reference-cycles-and-weak-links.md).
- **No catch-all type.** `JSON.parse` without a type argument is a compile
  error (`CP3208`), not `unknown`-with-runtime-everything; see
  [`docs/content/03-standard-library/09-json.md`](../content/03-standard-library/09-json.md)
  and [`docs/content/01-language/01-variables-and-bindings/02-types.md`](../content/01-language/01-variables-and-bindings/02-types.md).
- **`verify<T>` cannot distinguish "unparseable" from "shape mismatch".** Call
  `JSON.parse<T>` in `try`/`catch` when you need the distinction.
- **Rejection reasons are `Error`-typed.** `Promise.reject(v)` and an
  executor's `reject` both carry `Ref<Error>`; a non-`Error` reject value is
  not the supported path (the throw-only-`Error` law applies).
- **Class methods declared `async`** lower to coroutine bodies on the one
  event loop; `async` is not threads.
- **`std/log` does not exist.** The registry entry was removed; use
  `console.log`/`info`.
- **String-backed enums** are rejected in arithmetic and relationals (`CP3411`
  / `CP3406`); **`number` → enum** is rejected (`CP3401`).
