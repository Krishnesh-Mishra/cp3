# CP3 v0.2.4 — Automatic cycle reclamation, typed events and module boundaries

CP3 is a statically typed language with familiar TypeScript-shaped syntax that compiles ahead of time to native executables. v0.2.4 is the **automatic-memory release**: strong reference cycles among cycle-capable classes are reclaimed by a trial-deletion collector at the event-loop safe point, so `weak` is now an optimization rather than a requirement. The release also makes `EventEmitter<Events>` first-class, carries imports of classes, interfaces, type aliases, enums and plain records across module boundaries, and brings TypeScript-grade control-flow narrowing.

> **Rebuild note (post-release review):** the first v0.2.4 artifacts were pulled back after ten defects found in post-release use. All ten are fixed in this rebuild (see "Post-release review: ten fixes" below and the 102 new regression fixtures under `tests/cases/v0-2-4/issue1..10/`). The feature set is unchanged; the fixes are corrections, not new features.

> **Beta:** CP3 and its standard library are under active development. Check the repository documentation and the benchmark methodology before relying on feature semantics or comparing performance results.

## What's new

### Automatic reclamation of strong reference cycles

```cp3
class Node { value: number; next: Node | undefined; }
let root = new Node(1);
let other = new Node(2);
root.next = other;
other.next = root;                    // an ordinary unbroken cycle — no `weak`
console.log(root.next === other);
```

A strong reference cycle used to be a compile error (CP3401) unless the user broke it with a `weak` edge. v0.2.4 reclaims it automatically. The compiler builds the whole-program strong-reference graph and proves, per island, whether every edge is a walkable class handle. An island the collector can handle is freed once the whole island becomes unreachable — without a `weak` edge from the user, and without a tracing GC:

- no whole-heap tracing, no stop-the-world pause, no background collector thread;
- the collector runs at the event-loop safe point (never inside a macrotask), single-threaded, with a 4096-node / 200-microsecond budget per pass, resumable across passes and drained at loop exit;
- classes outside a cycle pay nothing: acyclic classes keep the ordinary `Ref<T>` handle byte for byte.

CP3401 is retired for a cycle only when every member of the component is collector-eligible; everything else keeps CP3401 (fail closed): an opaque edge (`object`/`unknown`/a type parameter/a native handle/a Promise), a record or closure field shape the visitor cannot enumerate, an interface field whose implementers it cannot walk, or an `auto-weak` candidate that is not yet proven. `weak` stays supported with the same semantics — an optional optimization (a deterministic earlier release), not a requirement.

### Typed `EventEmitter<Events>`

```cp3
interface Events {
    login: (userId: string) => undefined;
    logout: () => undefined;
    [key: string]: (...args: any[]) => undefined;
}
const bus = new EventEmitter<Events>();
bus.on("login", (userId) => { console.log(userId); });
bus.emit("login", "u-42");
bus.on("the-event", (ev) => console.log(ev));
bus.emit("the-event", "hello");
```

- The Events map drives `bus.on`/`bus.once`/`bus.off`/`bus.emit` typed checking: unknown event names are rejected with CP3305; arity and payload type are checked against the listener signature.
- Wildcard listeners (`bus.onAny(fn)` and `bus.offAny(fn)`) fire on every event outside the declared member set, only when the map has an index signature.
- `bus.isValidEventName("name")` narrows the argument inside the guarded branch so `bus.emit(name, ...)` type-checks afterwards (a runtime check for dynamic event names).
- Listeners are contextually typed: an un-annotated parameter `(m) => ...` inherits the payload type from the Events map (`m: Msg`).
- A class can `return this` from a method: the generated code now returns through the canonical `SharedBase` (`enable_shared_from_this`) so a self-returning call yields a fresh handle with the correct static type.

### Imported classes, interfaces, type aliases and enums usable across module boundaries

```cp3
import { RedisClient } from "./frame.cp3";
const redis = new RedisClient();
console.log(redis.id);
```

- Imported `export class`/`export interface`/`export type`/`export enum` are now usable in annotation, type guard, member-access and constructor positions from another `.cp3` file. The dep TU continues to own its struct emission; the consumer TU re-registers the AST to get `ClassModel`/`ObjectModel` and member/method signature info.
- `cp3c check` now emits the entire import graph (same path as `run`/`test`/`lsp`), so cross-file type errors show up under `check` and not only under `run`.
- Imported classes get `Ref<DepClass>` in the consumer TU: `new RedisClient()`, `RedisClient.prototype.ping()`, `class Foo implements RedisClient` etc. all work unmodified.
- Imported interfaces, aliases and enums register their names in the consumer unit, so a type imported from another file resolves in annotation positions and member-access narrowing just like a local declaration.
- The `.cp3` export/import of a cycle-capable class keeps its eligibility analysis on the whole import graph the importing unit sees.

### Collections are TypeScript-style ambient

```cp3
const map = new Map<string, number>();
const set = new Set<string>();
const queue = new Queue<number>();
console.log(map.get("a"));
```

`Map`, `Set`, `LRUCache`, `MultiMap`, `ConcurrentMap`, `Queue`, `Stack`, `PriorityQueue`, `RingBuffer` and `BitSet` are ambient builtins — values and type annotations resolve with no import, mirroring TypeScript. `std/collections` stays importable (`import { Map } from "std/collections"`) for source compatibility and narrows identically; there is no `std/collections/types` module by design (the family is ambient, the extra facade would be dead weight).

### Std types facades (annotation-only imports)

`std/<module>/types` modules re-export the stdlib's type names so annotation positions can import them without runtime dependencies:

```cp3
import { URL, URLSearchParams } from "std/url/types";
import { Buffer } from "std/buffer/types";
import { TextEncoder, TextDecoder } from "std/text/types";
import { Date } from "std/date/types";

const url: URL = new URL("https://example.com");
const buffer: Buffer = Buffer.from("hello");
```

Helpers available today: `std/network/types`, `std/buffer/types`, `std/url/types`, `std/date/types`, `std/text/types`. Type-only import exercises no runtime loader and is parsed at zero cost. (The `std/collections/types` facade does not exist — see above.)

### Index signatures in interface and object type literals

```cp3
interface Events {
    [name: string]: (...args: any[]) => undefined;
}
type HttpHeaders = { [name: string]: string; }
```

- Interfaces and object type literals accept `[name: string]: T` and `[n: number]: T` index signatures.
- The shape label `$o{...}` records the index signature; member access and assignability honor it.
- Object literals without all declared properties but with an index signature accept the extra properties.

### Narrowing is TypeScript-grade

```cp3
function parseFrame(f: Frame | undefined): Frame | undefined { return f; }
const frame = parseFrame(new Frame(7, undefined));
if (frame === undefined) return;
console.log(frame.id);
```

- `if (!x)` / `if (x)` narrow `x` to the truthy / falsy subset of its type. For a nullish union (`Box | undefined`), the truthy branch reads through the held handle, so `if (b) { console.log(b.a); }` and the `b ? b.a : -1` ternary compile out.
- `x === undefined` / `x !== undefined` / `x === null` / `x !== null` branches narrow the identifier; after `if (frame === undefined) return;` the use of `frame.id` type-checks without a cast.
- An assignment narrows the binding it targets: after `v = 4` a later read of `v` is a `number`, so `if (v === undefined) { v = 4; } return v + 1;` type-checks.
- The two arms of an `if` are merged the way TypeScript merges them: the code after the `if` sees the union of what the arms concluded; an arm that returns, throws, breaks or continues never reaches the merge point.
- Member, `this.x` and nested-chain receivers narrow: `if (node.next !== null) { node.next.value }`, `if (this.n === undefined) { return 0; }`, `if (a.b.c) { a.b.c.d }`. The narrowed receiver is unwrapped at the read site.
- `typeof x === "number"` / `typeof x === "string"` narrow `x` for nullish scalar unions (`number | undefined`, `string | undefined`) and for mixed scalar unions (`number | string`), which lower through `std::get` so the member/arith use site still type-checks.
- `typeof x === "object"` narrows `x` to the object-like members of its union (array/record/class/enum, plus `null` which JS reports as `"object"`); the false branch keeps the rest (including `undefined`).
- A union of all-literal members of one string family spells itself as the base family (`"a" | "b"` behaves as `string` at assignability sites). Number- and boolean-literal unions lower to their base families as well (`1 | 2` is assignable to/from `number`).
- A narrowed collection read (`arr.length`, a `for`-of iterable) no longer double-wraps the storage representation; storage sites read through the held handle.

### `object` is a usable annotation

```cp3
type Point = { x: number; y: number };
const p: Point = { x: 1, y: 2 };
const o: object = p;   // stores whatever the value holds
```

- `object` is CP3's "untyped value" spelling (the replacement for the retired `any`/`unknown`). It works as a declaration type: an `object`-annotated binding stores the initializer's value, whether that is a concrete record or an object literal.
- An `object` binding without an initializer is rejected (CP3401: "an 'object' binding needs an initializer").
- A member read off an `object` value is rejected (CP3401) — `object` has no members, as in TypeScript.

### Imported records keep their function members across files

```cp3
// dep.cp3
export const utils = {
    double: (n: number): number => n * 2,
    greeting: "hi",
    count: 3,
};
// main.cp3
import { utils } from "./dep.cp3";
console.log(utils.double(21));
```

- An exported object literal with arrow-function members now gets a full C++ representation, so its function members survive the export/import boundary as real callables (not erased data) and can be called, destructured and read from the importing unit.
- The imported object's plain-record shape label (`$o{...}`) is registered in the importing translation unit, so member access, destructuring and narrowing on an imported object behave like a local one.
- `export default` of an object literal is supported: the literal is lowered to a stable module-scope binding in the exporting unit and exposed to importing units through the same qualified C++ name the `export` statement registers (e.g. `import dep from "./dep.cp3"; dep.utils()`).

### LSP — stdlib-backed completions with auto-import

```text
consol
```

- Bare `console` completions carry an `additionalTextEdits` payload that inserts `import console from "std/console";` at the top of the file when accepted.
- Each `std/*` module's exported value is curated into the completion list (console, process, fs, io, Math, JSON, path, os, crypto, URL, URLSearchParams, Buffer, TextEncoder, TextDecoder); values that are already in scope (the ambient collections family, Promise, EventEmitter, Date, ...) are not re-offered.
- Type positions offer the matching `std/*/types` shadow (`Buffer`, `TextEncoder`, `Router`, ...); the ambient collections family is offered as a plain builtin.
- On accept, the editor writes the import into the buffer instead of producing out-of-scope errors.

### `Promise` combinators destructure like records

```cp3
const { promise, resolve, reject } = Promise.withResolvers<string>();
resolve("done");
```

`Promise.allSettled` and `Promise.withResolvers` records now destructure like plain object records because the runtime C++ record members (`$settled` / `$withResolvers`) map to field names automatically.

### Consistency and robustness fixes

- `s.slice()` / `a.slice()` (string and array) now honor the TS model: `start` and `end` are optional and explicit `undefined` arguments are omitted, not passed as a raw `undefined` value into C++.
- An object-typed field read through a narrowed receiver no longer emits `(storage)->field` against a nullable binding; it reads through the held handle as the model-member paths do.
- Generic member-call signatures substitute the receiver's type arguments (`Box<number>.get()` returns `number`, not the uninstantiated `T`).
- The `Self` return of a shared class body now routes through the canonical `SharedBase` so `return this` in a class is always a valid C++ expression returning the same ABI shape as the declaration.
- Object literals with extra function members register their exports so cross-file function members survive as callables (see above); `export default` of an object literal now binds a module-scope value the importing unit can call.
- `mapSlotType` bounds-checks before reading a function-signature slot, fixing a `size_t` underflow when a callee has no parameters.
- A typeof-narrowed identifier reads through `std::get` rather than through the C++ member access on a union payload.
- A bare narrowed identifier unwraps through `std::optional` instead of double-wrapping at `.length` sites (`for (const x of narrowed) x.length` compiles).
- `package.json` and the JSON manifest parser accept a leading UTF-8 BOM; `0xEF 0xBB 0xBF` is no longer a syntax error.

### Post-release review: ten fixes

The first v0.2.4 cut was pulled back after ten defects showed up in post-release use. All ten are fixed and covered by 102 new fixtures under `tests/cases/v0-2-4/issue1_object_typeof/` … `issue10_tcp_chunk_narrow/`:

| # | Defect | Fix |
| --- | --- | --- |
| 1 | `typeof x === "object"` did not narrow object handles out of a union (member read reported the null-receiver diagnostic) | the typeof guard partitions the declared union by `memberMatchesTypeof`; the true arm keeps the object-like members (`null` included) |
| 2 | `type U = 1 \| 2` did not lower (number literal unions stayed `number \| number`) | literal types carry the source spelling; number-literal equality compares exact-integer payloads |
| 3 | `export default { ... }` of an object literal was unusable from other files (CP3304) | the default object is lowered to a stable namespace-scope binding the link table resolves in the importing unit |
| 4 | `x instanceof Buffer` rejected the right operand | `Buffer` registers a builtin codegen model and is accepted at the `instanceof` check (error family rules) |
| 5 | `parseInt` return type (accuracy misunderstanding) | already returns `number` — regression fixtures added |
| 6 | a pure TCP client (no `createTcpServer`) failed at link with `undefined symbol: tcpServerForget` | `tcpServerForget` (and `TcpServerImpl::forget`) are inline in the shared TCP header; the server TU is no longer required for clients |
| 7 | `cp3 install <dir>` crashed | not reproducible — regression fixtures added (a `.cp3` program runs the local-directory install through `process.exec`) |
| 8 | `Map` as a class field / `.entries()` / `for-of` over a Map | `$mapEntry` lowers to `std::pair<K, V>`; `Map#entries()` arrays are storable and iterable |
| 9 | `T \| undefined` returns across module boundaries (cross-module interface return, `cp3_iface_Foo` mismatch) | interface wrappers are emitted at global scope by every unit (one-definition guard), so the wrapper type is one type everywhere |
| 10 | `typeof chunk === "string"` on the ambient TCP `data` chunk | verified working through the narrowing branch and at a typed boundary (loopback fixtures) |

Two further known gaps were found during that pass and are logged in `ROADMAP.md` (not fixed in this release): member reads on the ambient TCP chunk stay untyped (`typeof chunk.length` has no static answer; comparisons fold to `false`), and the compile cache's header fingerprint does not cover runtime private headers (stale per-fixture objects after a runtime-header edit; workaround: wipe each fixture's `.cp3/`).

### Diagnostics

- CP3305 (member not found) reports an event name that the Events map does not declare (`bus.emit("helllo", …)`).
- CP3403 (arity mismatch) reports `emit` calls whose payload count does not match the listener signature.
- CP3401 (type mismatch) reports a listener or payload that does not fit the Events map's listener signature (for example, a handler that declares more parameters than the map provides).
- CP3305 also guards against an unrepresentable `std/*/types` facade import being used as a value — the annotation shadow exists only in type positions.
- CP3401 keeps the same code and message for reference cycles the compiler cannot reclaim (see above); the same code is used for `object` member reads and `Maybe`/`optional` storage mismatches.

### Not changed

- JS semantics of `undefined`/`null`, `void`-returns, spread-`number[]` → fixed arity, `enum` member printing, loose-nullish equality (still false), literal-number-union spelling (still the base family).
- `Promise.withResolvers` returns a record addressed `$withResolvers`; the members lower to C++ handles and the destructuring works.
