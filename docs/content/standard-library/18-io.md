# I/O readiness

`std/io` exposes the reactor primitives for native libraries that already have a socket and a non-blocking step API. It does not make a blocking C call concurrent.

```ts
import io from "std/io";
```

## `waitReadable` and `waitWritable`

```ts
await io.waitReadable(fd); // Promise<undefined>
await io.waitWritable(fd); // Promise<undefined>
```

`fd` is a native socket descriptor: an `int` on POSIX, or the `SOCKET` value exposed by the native library on Windows. Keep it in the exact-integer range of `number`.

The wait suspends only the calling async function. Timers, promise continuations and other fd waiters continue on the same event loop. Many waiters can share a descriptor, including one reader and one writer.

The promise rejects when the poll reports an error, the peer hangs up or disconnects, the descriptor is invalid, or the descriptor is closed while the wait is registered. There is no cancellation token: a pending waiter stays pending until it settles or fails.

## `pollUntilDone`

```ts
await io.pollUntilDone(
  () => nativeLib.socket(handle),
  () => nativeLib.progress(handle),
);
```

`checkProgress` returns one of:

| Constant | Meaning |
| --- | --- |
| `io.POLL_READING` | Await `waitReadable(getSocket())`. |
| `io.POLL_WRITING` | Await `waitWritable(getSocket())`. |
| `io.POLL_DONE` | Resolve the promise. |
| `io.POLL_FAILED` | Reject the promise. |

`getSocket()` is called again on every iteration, so a connect sequence can move to a new descriptor. An unknown state rejects the promise.

## Event loop sharing

`std/io` and `std/network` share one event loop per thread (libuv-backed). A blocking C call with no pollable file descriptor cannot be made concurrent by this module or by wrapping it in `async`; it still blocks the loop.
