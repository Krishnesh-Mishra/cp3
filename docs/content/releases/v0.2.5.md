# CP3 v0.2.5 — native type widths, references intel, module navigation

CP3 is a statically typed language with familiar TypeScript-shaped syntax that compiles ahead of time to native executables. v0.2.5 is the **type-correctness and editor wave**: native integers across the type system, the LSP reference/navigation tooling brought up to speed for barrels, aliases and multi-file workspaces, the parser diagnostics the editor rides on, and one codegen crash fix at the C++ ABI boundary.

> **Beta:** CP3 and its standard library are under active development. Check the repository documentation and the benchmark methodology before relying on feature semantics or comparing performance results.

## What's new

### Direct declarations follow the package `typeSystem`

Under `typeSystem: "rust"` or `"cpp"`, the standard library's internal scalar surfaces are now typed by the corresponding native width instead of always `number` (TypeScript projects are unchanged):

- `s.length`, `arr.length`, `push`/`unshift` results, `arr.keys()`, `entries()`, `MemoryUsage` bytes, and `os` byte counts are the length/index width (`usize` on Rust, `size_t` on C++).
- `s.indexOf` / `lastIndexOf`, `arr.findIndex`, `binarySearch`, `keys()` indices are `isize` (Rust) / `ptrdiff_t` (C++).
- `parallel.for` and `parallel.reduce` induction variables use the type system's signed-index width; a Rust `i64`-seeded `parallel.reduce` now returns `i64` end-to-end, and the reduce surface stays in native integers for native seeds.
- Native integer literals assigned into a native binding adopt it (`let i: i64 = 0; i = 0; i = i + 1` — `i` is typed `i64` throughout). Under `rust`/`cpp` this makes the idiomatic counter patterns work without casts; under TypeScript nothing changes.
- Mixed spellings (`r_'i64'`, `c_'double'`, `ts_'number'`, `f32`, `u8`, `long`, `long long`) flow into every `number`-typed parameter of the internal APIs (`arr[45]`, `arr.indexOf(n)`, `Math.sin(n)`, `JSON.stringify(v, replacer, space)`, `Map.groupBy`/`Object.groupBy` callbacks), exactly as a `number` does.

Fixture family: `tests/cases/v0-2-5/typesystem-direct-decls/` — the same assertions pinned for Rust, C++ and TypeScript. See ["A Rust project sees exact widths"](../standard-library/../language/01-variables-and-bindings/02-types.md) for the Rust-typed index-value example (the previous behavior — every direct declaration spelling `number` — is gone).

### Interface methods may return native value types

`interface Drawn { area(): i64 }` now compiles, with the interface-dispatch path carrying `std::int64_t` (and every other native spelling) through the wrapper thunks exactly the same way `number`/`string`/`boolean` are carried. Under the previous release this produced a `CP3401` at the dispatch call site. See the pinned case `tests/cases/v0-2-5/checker-correctness/interface_native_return/`.

### Editor and language-server intel across modules

The 0.2.5 wave fixed a family of cross-module navigation defects. The pinned tests live under `tests/lsp/`; the same family the editor reports against is covered by a frozen fail-then-pass set:

- **Cross-module barrels / re-exports / default exports.** Goto-definition, references, rename and hover work through the barrel (`export { combine as merge } from "./a.cp3"`, `export * from "./a.cp3"`, `export default …`) into the declaring module; consumer modules are found when the anchor is the declaration or the specifier.
- **Companion modules.** Use-sites resolve the sibling module's declarations (`import { Config } from "./companion.cp3"`): annotations, member reads, implements clauses, type arguments and new expressions.
- **Same-file goto-definition.** Member types, `this.<member>`, implements clauses, alias-before/after-class-use, and interface conformance all resolve to the declaring span.
- **References at type positions.** Annotations, `implements`, `extends`, enum member lists, `new T()`, generic witnesses and the same-name member across sibling classes all collect.
- **Member completion** for receivers typed in another module (import, default import, ambient/global), and for sibling subclasses: the completion surface follows the real shape table of the receiver instead of the entry file's top-level walks.
- **Generic instantiation intel.** `Box<string>` narrowing works on hover (`value: string`), calls (`identity<number>(3)` returns `number`), and the completion asks against the member table at the instantiation.
- **Call-hierarchy edges carry their call-site ranges** and the merged per-caller entry, and `prepareCallHierarchy` answers at declaration positions.
- **Rename propagates across module boundaries**, including alias renames inside the barrel chain and across the consumer module.
- **Type hierarchy at the interface declaration** answers at implements sites that previously produced no items.

The fixture reports `tests/lsp/cross_module_check.py` (28 checks), `tests/lsp/refs_type_positions_check.py` (22), `tests/lsp/goto_same_file_check.py` (10), `tests/lsp/generic_intel_check.py` (12), `tests/lsp/completion_visibility_check.py` (14) and `tests/lsp/hierarchy_parser_check.py` (11) pin fail-then-pass behavior of the extension. `rename_check.py` verifies the same for rename propagation; `goto_same_file_check.py` for member-sites.

### Parser diagnostics

- An empty import specifier list (`import {} from "std/math"`) is now a diagnostic: `CP3209`, anchored at the brace span. (Otherwise silently accepted before.)
- A missing close paren reports `CP3202` instead of being silently consumed (3a1dfa50 was already in v0.2.4).

### Codegen fixes at C++ ABI boundaries

- **0.2.4 bug (`object-churn`)**: value-typed arrays of class instances — `const kept: Cell[] = []; kept.push(new Cell(...))` — emitted a `Ref<Cell>` push against `Array<Cell>` storage, and the emitted C++ did not compile. The push path now recognizes the value-array case before the generated allocator runs, and matches the value ABI.
- **0.2.4 bug (`block-local fresh arrays`)**: block-local `const dist: number[] = [];` lowered to a stack `std::vector<T>` and a raw pointer, then handed the raw pointer to `Array<T>`-typed runtime calls (`arrayWriteAt`, `arrayAt`). Block-local fresh arrays now lower to the owned `Array<T>` form (identical ownership to module-level arrays), so the generated program compiles.
- A fresh **runtime mirror** no longer dies on fresh builds: native rows re-listing an always-available include root produced duplicated include dirs and the `_runtime` mirror copy reported `File exists`; the duplication is removed and the mirror skips byte-identical destinations.

## What was fixed

- `JSON.stringify(v, undefined, i64)` no longer reported `cannot serialize this value` when the `space`/`replacer` arguments were native integers; every numeric argument (including exact rust integers) is accepted and lowered through `json::value` directly.
- `str[i]`, `arr[i]` etc. accepted the whole numeric family as a subscript; the compiler stops caring whether the index is `i64`, `f32`, `double` or `ts_'number'` — any numeric value type works as an index, and so does the literal itself in a rust-typed program.
- The compiler used to return the same `number` for `str.length`, `arr.length`, `str.indexOf`, `arr.findIndex`, etc. irrespective of the `typeSystem`; all of those are now lowered by the width table (`usize` on rust, `size_t` on cpp, `number` on TypeScript).
- `let i: i64 = 0; i = 0; i = i + 1` previously failed with `CP3401`; literal assignments to native bindings now adopt the native binding.
- Duplicate `cp3c.exe` contents in the `_runtime` mirror (`cannot copy '...\include\...\buffer.hpp' to '...\runtime\_mirror\...' File exists') — the include dirs are deduplicated and byte-identical destinations skip the copy.
- Empty array literals take the target's element type in all contexts (`const arr: number[] = [];` requires no cast).

## What changed behaviorally

- Under `typeSystem: "rust"`, an array `length` is now `usize` rather than `number`. Code that mixed it with plain `number` variables without a conversion will produce diagnostics on Rust projects; **the TypeScript and untyped paths are unchanged**.
- `let a = 23` in a rust/cpp project infers a native integer default (`i32` when it fits), in untyped code in a TypeScript project it is still `number`.
- `Array.length`, `String.length`, etc.
