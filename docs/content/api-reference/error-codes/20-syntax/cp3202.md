# CP3202 — Expected token

**Stage:** parser · **Const:** `diagcode::kExpectedToken`

## What it means
The parser is waiting for a specific token and the current token is not it. Where CP3201 is the general shape error, this code is used when the expected token is known exactly.

## Why it fires
Every `expect(TokenKind::X, "…")` failure routes here (`src/parser/src/core/tokens.cpp`), as do a few explicit sites: `expected 'while' after 'do' body`, `expected '>'`, `expected a name in the index signature`. The parser's `report()` prefixes the message with `syntax error: `, so the printed diagnostic reads `syntax error: …`. The wording after the prefix varies by site; what is stable is that a single awaited token never arrived.

## Minimal reproducer
```ts
// fails with CP3202
while (ready {
  tick();
}
```
The `while` header never sees `)` — the parser reports `syntax error: expected ')' after while condition`. The legal form closes the parenthesis before the body: `while (ready) { tick(); }`. This case is not pinned by a `tests/cases/` fixture; the code and message are wired in `src/parser/src/stmt/statements.cpp` (via `expect(RParen, …)`). Message wording may vary across sites; the code is what is stable.

## What happens
Compilation stops before semantic analysis; nothing is produced. The diagnostic carries `CP3202` and points at the token in place of the awaited one.

## How to fix
1. Read the message after `syntax error: ` — it names the awaited token (`expected ')'`, `expected '>'`, `expected 'while' after 'do' body`, …).
2. Insert the awaited token at the reported span; most cases are an unclosed parenthesis, bracket or generic parameter list.
3. If the awaited token is genuinely absent because of a larger mistake (a stray `}` earlier), fix the earlier construct — cascade errors downstream usually disappear.
