# CP3204 — Invalid assignment target

**Stage:** parser · **Const:** `diagcode::kInvalidAssignmentTarget`

## What it means
The left-hand side of an assignment is not something that can hold a value: a literal, a call result, a `typeof`/other unary expression, or an index of a string.

## Why it fires
Two stages own this. The parser checks the target after seeing the assignment operator: if the left side is not an assignable target it reports `invalid assignment target` (`src/parser/src/expr/expressions.cpp`) — for example `5 = 3`. Semantic analysis repeats the check for shapes only it can judge: `s[0] = 'x'` on a string reports `cannot assign to the index of a string; strings are immutable (use string methods like replace / substring / slice)` (`src/sema/src/checks/expr/ops_check.cpp`). Code generation repeats the diagnostic again so a bad target never reaches C++ (`src/codegen/src/emit/control/assignment.cpp`).

## Minimal reproducer
```ts
// fails with CP3204
const f = (): number => 1;
f() = 5;
```
A call result cannot be assigned to, so the parser reports `invalid assignment target`. The legal form assigns to a variable, a property of an object or class instance, or an array element. This case is not pinned by a `tests/cases/` fixture; the parser check is `isAssignableTarget` in `src/parser/src/expr/expressions.cpp` — message wording may vary by site, the code is stable.

## What happens
Compilation stops before semantic analysis (parser path) or before code generation (sema path); nothing is produced. The diagnostic carries `CP3204`.

## How to fix
1. Move the value into a binding: assign to a variable, a property, or an array element instead of the expression’s result.
2. For the string-index form, use the string methods named in the message (`replace`, `substring`, `slice`) — strings are immutable in cp3.
3. Check the preceding expression: an accidental extra `()` or operator in the left-hand side usually explains a target that "looks" assignable.
