# CP3205 — Invalid statement

**Stage:** parser · **Const:** `diagcode::kInvalidStatement`

**Reserved / not currently emitted by the compiler.** The code is frozen in the diagnostic table but no emission site in `src/` reports it. No `tests/cases/` fixture pins CP3205.

## What it means
Reserved for a statement in an illegal position. If a future compiler starts reporting it, this page describes the meant situation.

## Why it fires
Not in this tree. Statement-level grammar violations are reported today through the general parser paths — CP3201 (`src/parser/src/core/tokens.cpp`) — and the decisions record names `CP3205` for the `extends A, B` multiple-inheritance case, but in this source tree `class C extends A, B` reports CP3201 `multiple inheritance is not supported` (`src/parser/src/decl/declarations.cpp`, pinned by `tests/cases/classes/02/multiple/multiple_inheritance`, whose output.json carries `"code": "CP3201"`). The constant is kept so existing test expectations and tools referencing it keep a stable meaning.

## Minimal reproducer
Not constructible today. The canonical shape of the situation — clearly labeled as such, not a reproducer for CP3205 itself:

```ts
// shape — reserved. The nearest real case is the one the design record
// names; today it reports CP3201, pinned by
// tests/cases/classes/02/multiple/multiple_inheritance
class A { }
class B { }
class C extends A, B { }
```

## What happens
If it ever fires: compilation stops before semantic analysis; nothing is produced; the diagnostic carries `CP3205`. Today the same shape reports CP3201 (or a nearby parser code) at the offending statement.

## How to fix
There is nothing to fix in the compiler's current output for this code. If you believed you had an "invalid statement", look at the first CP3201/CP3202 diagnostic instead and fix that; for the `extends A, B` shape, write one base class per declaration — multiple inheritance is not supported in cp3.
