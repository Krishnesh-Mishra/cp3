# CP3207 — Missing semicolon

**Stage:** parser · **Const:** `diagcode::kMissingSemicolon`

## What it means
A statement ended but no `;` was found, and the line did not break in a place where automatic semicolon insertion applies.

## Why it fires
`consumeSemicolon()` (`src/parser/src/core/tokens.cpp`) inserts a semicolon only in three cases: an actual `;` follows; the next token is `}` or end of file; or the line breaks before the next token (ASI). Anything else reports `expected ';'`, which the parser prefixes to `syntax error: expected ';'`. Two statements on one line are the canonical trigger — `const a = 1 const b = 2;`.

## Minimal reproducer
```ts
// fails with CP3207
const a = 1 const b = 2;
```
The `const b` starts on the same line as the first declaration with no `;` in between, so no ASI applies and the parser reports `syntax error: expected ';'`. The legal form is `const a = 1; const b = 2;` or a newline between the statements. This case is not pinned by a `tests/cases/` fixture; the check is `consumeSemicolon` in `src/parser/src/core/tokens.cpp`.

## What happens
Compilation stops before semantic analysis; nothing is produced. The diagnostic carries `CP3207` and points at the token that followed the missing `;`.

## How to fix
1. Insert the `;` at the end of the statement.
2. Or put the next statement on a new line — cp3 applies ASI across a line break, the same way TypeScript does.
3. If a statement already ends in a block (`if`, `for`, function body), no `;` is needed — if the diagnostic points right after the block's `}`, the problem is more likely a missing `;` on an earlier simple statement.
