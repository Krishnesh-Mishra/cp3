# CP3206 — Expected declaration

**Stage:** parser · **Const:** `diagcode::kExpectedDeclaration`

## What it means
`export` was followed by something that is not a declaration. An export must introduce a `function`, `class`, `interface`, `type`, `enum`, `const`/`let`/`var` binding or an import/export list — not an arbitrary statement or expression.

## Why it fires
When the parser sees `export` followed by anything `parseDeclaration` cannot handle, it reports `expected a declaration after 'export'` (`src/parser/src/core/parser.cpp`). A bare `export 42;`, `export +x;` or `export return …;` are all this case. The parser prefixes the message with `syntax error: `.

## Minimal reproducer
```ts
// fails with CP3206
export 42;
```
There is no declaration for `export` to bind, so the parser reports `syntax error: expected a declaration after 'export'`. The legal spelling is an actual declaration — `export const answer = 42;` — or an export list such as `export { answer };`. This case is not pinned by a `tests/cases/` fixture; the emission site is quoted from `src/parser/src/core/parser.cpp`.

## What happens
Compilation stops before semantic analysis; nothing is produced. The diagnostic carries `CP3206`; the parser recovers by treating the declaration as absent.

## How to fix
1. Add the missing declaration keyword: `export const …`, `export function …`, `export class …`, `export interface …`, `export type …`, `export enum …`.
2. If you meant to export existing names, use the list form: `export { a, b as c };` or `export { a } from "./mod.cp3";`.
3. If the token after `export` is a typo (for example `exprot` elsewhere), fix the source — this diagnostic only fires where `export` was actually parsed.
