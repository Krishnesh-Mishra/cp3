# CP3203 — Unexpected end of input

**Stage:** parser · **Const:** `diagcode::kUnexpectedEof`

**Reserved / not currently emitted by the compiler.** The code is frozen in the diagnostic table but no emission site in `src/` reports it. End-of-file problems are reported today as CP3201/CP3202 (the parser reaches its `EndOfFile` token and an awaited token is reported missing, or the current shape is reported as unexpected), and unterminated literals/comments as CP3102–CP3104. No `tests/cases/` fixture pins CP3203.

## What it means
Reserved for "the source ended in the middle of a construct." If a future compiler starts reporting it, this page describes the meant situation.

## Why it fires
Not in this tree. The parser terminates every stream with an `EndOfFile` token, so "unexpected end of input" surfaces through the ordinary expectation paths rather than through a dedicated diagnostic (`src/parser/src/core/tokens.cpp`). The constant exists so tests and tooling can rely on a stable code if that changes.

## Minimal reproducer
Not constructible today. The canonical shape of the situation — clearly labeled as such, not a pinned fixture:

```ts
// shape — reserved; a truncated source such as an unfinished declaration.
// Today this yields CP3201/CP3202 (or CP3102 for an open string), not CP3203.
const x = { a: 1
```

## What happens
If it ever fires: compilation stops before semantic analysis; nothing is produced; the diagnostic carries `CP3203`. Today, a truncated file instead yields the CP3201/CP3202 (or CP3102) diagnostic at the point where the parser ran out of tokens.

## How to fix
There is nothing to fix in the compiler's current output for this code. For a truncated file, look at the first CP3201/CP3202/CP3102 diagnostic instead — it points at the exact construct that ran out of input — and close the construct (a missing `}`, `)`, quote or backtick).
