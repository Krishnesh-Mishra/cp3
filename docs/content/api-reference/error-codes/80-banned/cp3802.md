# CP3802 — Undeclared property

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kUndeclaredProperty`

## What it means
An assignment names a property the class does not declare. A cp3 class has a fixed field set, so writing a new field is not allowed — the program must not "grow" objects at a call site.

## Why it fires
Checked in semantic analysis when an assignment target is a member access on a class instance (`src/sema/src/checks/class/class_check.cpp`): the member must exist in the class (or its bases). On an assignment target — as opposed to a read — a miss reports `cannot assign to undeclared property '<name>' of class '<name>'` (reads report CP3305 with candidate names instead).

## Minimal reproducer
```ts
// fails with CP3802
class C { x: number = 1; }
let c = new C();
c.y = 2;
```
The legal form declares the field on the class (`class C { x: number = 1; y: number = 0; }`) or adds it at construction time. Pinned by `tests/cases/classes/03/undeclared/undeclared_field_assign_error` (placeholder code, `contains` the member).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Declare the field on the class (a public field is the usual spelling).
2. If the field is only sometimes present, give it a default value or type it as a union including `undefined`.
3. If you want an extensible bag of values, use a `Map<K, V>` field instead of ad-hoc properties.
