# CP3804 — arguments is banned

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kArgumentsBanned`

## What it means
The `arguments` object is banned. CP3 functions declare their parameters explicitly, and an implicit arguments vector would hide the fixed signature.

## Why it fires
Checked in the expression/call passes of semantic analysis when an identifier named `arguments` appears (`src/sema/src/checks/type/banned.cpp`, wired from `expr_check.cpp` and `call_check.cpp`). The diagnostic reports `the 'arguments' object is banned; use a rest parameter instead`.

## Minimal reproducer
```ts
// fails with CP3804
import console from "std/console";
function f(a: number): undefined {
  console.log(`${arguments.length}`);
}
f(1);
```
The legal form uses a rest parameter (`function f(...rest: number[]): undefined { ... }`). Pinned by `tests/cases/variables/01/arguments/arguments_banned` (placeholder code, `contains: "arguments"`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Use a rest parameter and spread: `function f(...args: number[]): undefined { console.log(`${args.length}`); }`.
2. If you only want arity, declare the parameters and read the count from them (`rest.length`).
3. If you want to forward arguments, pass them through as an array (`f(...args)`) or declare exactly the parameters you forward.
