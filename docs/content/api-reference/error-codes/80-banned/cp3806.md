# CP3806 — any is banned

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kAnyTypeBanned`

## What it means
The `any` type is banned. CP3 is statically typed with no escape hatch: an `any` annotation would opt a value out of the whole type system.

## Why it fires
Checked in the type-resolution pass of semantic analysis, in every annotation position (variables, parameters, returns, type arguments, aliases — `src/sema/src/checks/type/banned.cpp`, wired from `type_check.cpp`). The diagnostic reports `the 'any' type is banned; use 'unknown' or a concrete type`. Note the printed remedy predates the current rules: the `unknown` spelling is itself retired (CP3421), so prefer a concrete type, or `object` for a genuinely untyped value.

## Minimal reproducer
```ts
// fails with CP3806
function f(): undefined { }
let x: any = 5;
f();
```
The legal form annotates with a concrete type (`let x: number = 5;`), or `object` for an untyped slot. Pinned by `tests/cases/types/01/any/any_annotation_banned`, `any_param_banned` and `any_return_type_banned` (placeholder code, `contains: "any"`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Write the concrete type you mean: `let x: number = 5;` / `function f(a: string): undefined { }`.
2. If the value's type is genuinely not static, use `object` (an untyped-but-opaque value) rather than `any`.
3. If the value is passed through uninspected, consider generics (`function id<T>(x: T): T`) instead of a type-erasing annotation.
