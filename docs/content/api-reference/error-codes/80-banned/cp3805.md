# CP3805 — for...in over a plain object is banned

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kForInPlainObjectBanned`

## What it means
`for...in` over a plain object — or a class instance other than `Map`/`Set` — is banned. The keys of a fixed-shape object are known at compile time, so iterating them at runtime is redundant and easy to get wrong.

## Why it fires
Checked in the statement pass of semantic analysis for `for...in` loops (`src/sema/src/checks/type/banned.cpp`, wired from `stmt_check.cpp`): if the right-hand type is a plain object type or a class instance other than `Map`/`Set`, the diagnostic reports `for...in over a plain object is banned (its keys are known at compile time); use Map<K, V> or access fields by name`. Tuples and ambient types are excepted.

## Minimal reproducer
```ts
// fails with CP3805
import console from "std/console";
let o = { a: 1, b: 2 };
for (let k in o) {
  console.log(k);
}
```
The legal form iterates with `for...of` over a `Map`/`Set`, or accesses the fields by name (`o.a`, `o.b`). Pinned by `tests/cases/variables/01/forin/forin_plain_object_banned` (placeholder code, `contains: "for...in"`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Use a `Map<K, V>` (`for (const [k, v] of m) { ... }`) when the key set is decided at runtime.
2. Access the fields by name — the object's keys are fixed, so enumerate them explicitly.
3. For arrays, use `for...in` only for indices if really needed, or better `for...of`; for collections of class instances, iterate the collection, not the instance's fields.
