# CP3801 — delete is banned

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kDeleteBanned`

## What it means
The `delete` operator is banned. A cp3 object has a fixed shape, so there is no removable field to delete; `delete` is a JavaScript-ism with no meaning here.

## Why it fires
Checked in the operator/statement passes of semantic analysis when a `delete` expression is reached (`src/sema/src/checks/type/banned.cpp`). The diagnostic reports `the 'delete' operator is banned; a fixed-shape object has no removable fields (use Map<K, V>.delete)`.

## Minimal reproducer
```ts
// fails with CP3801
import console from "std/console";
const words: string[] = ["alpha", "bravo"];
const word = words[0];
delete words[0];
console.log(word);
```
The legal form replaces the value with a sentinel, or uses a `Map`/`Set` where deletion is meaningful (`m.delete(key)`). Pinned by `tests/cases/perf-array/01/delete/delete_element_check`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. If you need key deletion, use `Map<K, V>` and `m.delete(key)` — that is what the message points to.
2. If you need "no longer present" on an object, set the field to `undefined` or a sentinel value, or drop the field from the shape type.
3. If you were clearing a collection slot, use the collection's own API (e.g. `array` has no `delete`; use a new array or a sentinel).
