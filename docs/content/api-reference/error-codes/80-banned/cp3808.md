# CP3808 — Decorators are unsupported

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kDecoratorsUnsupported`

## What it means
A decorator (`@Name`) is used somewhere it cannot be, or no compile-time macro resolves it. CP3 does not run code while a class is being defined and emits no runtime metadata, so decorators are compile-time macros only — and this build has no macro resolution for them.

## Why it fires
Checked in the parser — a decorator on any declaration other than a class or class member reports CP3808 (`decorators are compile-time macros only` is part of that message) — and rejected again at the end of class analysis in semantic analysis (`src/sema/src/support/declarations.cpp`): any decorator attached to a class has nothing to resolve it, so it reports the same code with the wording about a `comptime function` rewriting the AST. A decorator in this build is never a legal program.

## Minimal reproducer
```ts
// fails with CP3808
@Decorator
class C { }
```
The legal form declares the class plainly (no decorator). Pinned by `tests/cases/generics/01/decorator/decorator_banned` (`CP3808`).

## What happens
Compilation stops (parser for misplaced decorators, front end for class decorators); nothing is emitted; the diagnostic carries the code.

## How to fix
1. Remove the decorator. CP3 emits no runtime metadata, so it would have no effect anyway.
2. If the decorator did something (validation, registration), perform the equivalent explicitly — a call, an `init()` step, or a build-time code generator.
3. If you are authoring a library that genuinely needs AST rewriting, that is the `comptime` macro surface, which is not available in this build; watch the release notes for it.
