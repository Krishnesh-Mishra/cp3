# CP3803 — Index signature is banned

**Stage:** semantic analysis — banned patterns · **Const:** `diagcode::kIndexSignatureBanned`

## What it means
An index signature or dynamic-key index access on a plain object is banned. A cp3 object type has a fixed key set known at compile time; dynamic or computed keys belong to `Map<K, V>`.

## Why it fires
Checked in the type-resolution and member-access passes of semantic analysis. Sources report, depending on the site: `index access on a plain object is not supported; its keys are fixed at compile time` (indexing a fixed-shape object), `Record<K, V> requires K to be string` (a non-string `Record` key), `index-signature object types are not supported; use Map<K, V> instead` (an `[key: string]: T` member in an object type), `index into Record<string, V> must be a string`, and — in generic contexts — `a computed object key is not supported: an object's keys are fixed at compile time`. See `src/sema/src/checks/type/type_check.cpp`, `src/sema/src/checks/expr/member_check.cpp` and `src/codegen/src/support/core/generic.cpp`.

## Minimal reproducer
```ts
// fails with CP3803
import console from "std/console";
interface Point2 { x: number; }
function getX<T extends Point2>(p: T): number { return p.x; }
let k = "x";
console.log(`${getX({ [k]: 5 })}`);
```
The legal form uses a fixed key (`getX({ x: 5 })`) or a `Map<K, V>` for dynamic keys. Pinned by `tests/cases/generics/01/generic/generic_computed_key_dynamic_error` (an interface literal with a dynamic computed key, `CP3803`).

## What happens
Compilation stops at the front end (or at monomorphization for the generic case); nothing is emitted; the diagnostic carries the code.

## How to fix
1. Replace the index signature with a `Map<K, V>` field; for `Record<string, V>` shapes, make the key `string` explicitly.
2. Replace dynamic indexing on an object literal with a fixed key, or with `Map`.
3. If you need a compile-time key set that is not yet known, widen the object type or use generics over fixed keys.
