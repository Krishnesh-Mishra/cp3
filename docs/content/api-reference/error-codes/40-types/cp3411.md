# CP3411 — Mixed type arithmetic

**Stage:** semantic analysis — types · **Const:** `diagcode::kMixedTypeArithmetic`

## What it means
Arithmetic or bitwise operators are applied to operands that do not share a numeric type — most commonly `string` and `number`, or two native integers with different signedness.

## Why it fires
Binary operator checking (`src/sema/src/checks/expr/ops_check.cpp`) rejects any operator whose operands are not both numbers (or both strings, for `+`): `type mismatch: mixed-type arithmetic with '<op>' on '<l>' and '<r>' (…)`, usually with a suggestion such as `parseTo(x, i64)` attached. The native tier (`src/sema/src/checks/type/native_types.cpp`) reports the same code for a sign mismatch — `type mismatch: cannot mix signed '<l>' with unsigned '<r>'; convert one side explicitly, e.g. parseTo(x, u64)…` — and, when `strictNumericCasts` is enabled, for two different native widths. An integral literal that fits adopts the native side instead of widening to `number` (`n % 2` stays native); it is the genuinely incompatible pair — `string` with `number`, signed with unsigned — that is rejected.

## Minimal reproducer
```ts
// fails with CP3411
const n = "str" - 4;
```
`string` and `number` are not both numbers and not both strings, so the compiler reports `type mismatch: mixed-type arithmetic with '-' on 'string' and 'number' (both operands must be number)` with a `parseTo` suggestion. The legal spelling converts explicitly: `parseTo("str", number) - 4`. This exact case is pinned by `tests/cases/v0-2-2/mixed_arith_suggestion`. `tests/cases/types/03/native_checked/mixed_signedness` pins the signed/unsigned native flavor in a rust-type-system project.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3411` and spans the operator, usually with a `parseTo` suggestion.

## How to fix
1. Apply the suggestion: convert the odd side with `parseTo(x, number)` / `parseTo(x, <target>)`.
2. For `+` on strings, decide whether you wanted string concatenation (make both sides strings) or numeric addition (convert both sides to `number`).
3. For native sign mismatch, convert one side explicitly to the other's signedness/width; the message names both conversions.
