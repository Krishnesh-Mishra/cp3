# CP3410 — Missing property

**Stage:** semantic analysis — types · **Const:** `diagcode::kMissingProperty`

## What it means
A required property of the target type is absent from the value being assigned: an object literal (or a class instance) assigned to a shape that demands it.

## Why it fires
`emitObjectDiff` (`src/sema/src/checks/expr/assignability.cpp`) walks the target shape's fields; a required (non-optional) target field with no corresponding source field reports `missing required property '<name>' in object literal`. The same diff runs for object literals assigned to class instances via `emitLiteralToClassDiff` (`src/sema/src/checks/class/class_conform_check.cpp`) when the class requires the field and it has no initializer. No `tests/cases/` fixture pins this code; the rule and message are quoted from source.

## Minimal reproducer
```ts
// fails with CP3410
interface Point { x: number; y: number; }
const p: Point = { x: 1 };
```
`y` is required by `Point` and absent from the literal, so the compiler reports `missing required property 'y' in object literal`. The legal form supplies `y` (`{ x: 1, y: 2 }`) or makes the field optional in the interface. This case is not pinned by a `tests/cases/` fixture; the rule is `emitObjectDiff` in `src/sema/src/checks/expr/assignability.cpp`.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3410` and spans the object literal.

## How to fix
1. Add the missing property to the literal.
2. Or declare the field optional in the target type (`y?: number`) if it genuinely may be absent — do this only if downstream code handles the absence.
3. If the literal is built up over several statements, assemble it in one expression or a variable annotated with the full shape; sema checks one literal against the whole target.
