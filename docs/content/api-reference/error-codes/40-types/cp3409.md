# CP3409 — Excess property

**Stage:** semantic analysis — types · **Const:** `diagcode::kExcessProperty`

## What it means
A fresh object literal carries a property the target type does not declare. The literal is not assignable as written.

## Why it fires
Object-literal assignability compares shapes structurally (`src/sema/src/checks/expr/assignability.cpp`, `emitObjectDiff`). For a *fresh* literal — a literal assigned straight to a variable, argument or property with a known target shape — any field not present in the target reports `excess property '<name>' is not part of the target type`. The same diff runs for literals assigned to class instances (`emitLiteralToClassDiff`, `src/sema/src/checks/class/class_conform_check.cpp`). A spread element is checked against the same target (see the pinned fixture, which spreads a variable and adds one extra property), so the error fires there too when the extra key is statically known.

## Minimal reproducer
```ts
// fails with CP3409
function take(o: { x: number }): number { return o.x; }
take({ x: 1, y: 2 });
```
The literal has no `y` in the target type, so the compiler reports `excess property 'y' is not part of the target type`. The legal forms drop the extra property or declare `y` in the target type. The pinned spread flavor is `tests/cases/functions-closures/02/object/object_literal_excess_property` (`take({ ...a, extra: 3 })` → CP3409).

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3409` and spans the object literal (or the spread) carrying the extra key.

## How to fix
1. Delete the property if it is not meant for this target, or declare it in the target type.
2. If the property is intentional, widen the target: add `y: number` to the parameter's object type (or give the interface the field).
3. If the object is deliberately a superset, introduce an intermediate variable first (`const t = {…}; take(t)`) — fresh-literal excess checking applies only to literals; the variable's shape is compared structurally without the excess-property rule.
