# CP3413 — Cannot instantiate abstract

**Stage:** semantic analysis — types · **Const:** `diagcode::kCannotInstantiateAbstract`

## What it means
`new AbstractClass(...)` for a class declared `abstract`. An abstract class may not be constructed; it exists to be extended.

## Why it fires
Class instantiation checks (`inferUserConstruct`, `src/sema/src/checks/class/class_conform_check.cpp`) look the class up in the class table; if the class is marked abstract, the construct reports `cannot instantiate abstract class '<name>'` instead of building the value. The diagnostic fires at the `new` expression, before arguments are checked. Deriving from an abstract class and instantiating the subclass is the supported form; the subclass must implement every abstract member, or the *subclass* is itself abstract.

## Minimal reproducer
```ts
// fails with CP3413
abstract class Shape { abstract area(): number; }
const s = new Shape();
```
`Shape` is abstract, so `new Shape()` reports `cannot instantiate abstract class 'Shape'`. The legal spelling derives a concrete subclass — `class Circle extends Shape { area(): number { … } }` — and constructs that. This case is pinned by `tests/cases/classes/01/abstract/abstract_instantiate_error` whose `output.json` uses the `"CP3xxxx"` wildcard with `contains: "abstract"` (the fixture deliberately does not pin a code); the emission site is `inferUserConstruct` in the class-conformance unit.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3413` and spans the `new` expression.

## How to fix
1. Derive a concrete subclass implementing every abstract member, and construct that instead.
2. If the base class needs no abstract members, remove the `abstract` modifier — then it may be constructed directly.
3. If you genuinely need a partial value of the abstract type mid-construction, restructure so the value is completed in the constructor of a concrete subclass.
