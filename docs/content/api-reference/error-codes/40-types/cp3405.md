# CP3405 — Not indexable

**Stage:** semantic analysis — types · **Const:** `diagcode::kNotIndexable`

## What it means
A value is indexed (`v[i]`) when its type supports no index operation: index reads are defined on arrays, strings, typed arrays, and `Map`/`Record`-shaped receivers — not on plain class instances, `Set`s or namespace objects.

## Why it fires
Unlike most CP34xx codes, this one is reported at the emission stage, not in sema (`src/language/typed-arrays/codegen_methods.cpp`): semantic analysis lets the read through with a permissive type, and the code generator — which must lower the read to a concrete C++ operation — reports `value of type '<T>' is not indexable (an index read is defined on arrays, strings and typed arrays)` when the receiver has no index operation (a class instance, a `Set`, a namespace object). It therefore surfaces during `cp3 build` / `cp3 run` / `cp3 dev` rather than always under `cp3 check`. An index into `unknown` reports CP3414 instead ("cannot index into type 'unknown'"), and a non-string key into `Record<string, V>` reports CP3803.

## Minimal reproducer
```ts
// fails with CP3405
import console from "std/console";
class Box { value: number; }
let b = new Box();
console.log(b[0]);
```
`b` is a class instance with no index operation, so the index read reports `is not indexable`. The legal form indexes an array, a string, a typed array, or a `Map<K, V>` with a string key. This exact case is pinned by `tests/cases/typed-arrays/02/index/index_on_class_instance`.

## What happens
Compilation stops at the code-generation stage; nothing is produced. The diagnostic carries `CP3405` and spans the index expression.

## How to fix
1. If you wanted an array, make it an array: `const xs: number[] = …; xs[0]`.
2. If you wanted key access on an object shape, use a declared property or a `Map<string, V>` (`map.get(key)`).
3. If the receiver is `unknown`, narrow it first — see CP3414.
