# CP3403 — Arity mismatch

**Stage:** semantic analysis — types · **Const:** `diagcode::kArityMismatch`

## What it means
A call passes too many or too few arguments (or a spread where none is allowed). The signature's parameter count is the source of truth.

## Why it fires
Every call is checked against its signature (`checkArgs` in `src/sema/src/checks/call/call_check.cpp`): `arity mismatch: expected N to M, got K argument(s)` for ordinary calls (with a dedicated continuation note for the `std/network` `next()` callback), and `a spread argument must be the last argument of a call with a fixed argument list` when a spread is not in final position. The same code fires for too-many/too-few constructor arguments, for `parseInt`/`atob`/`btoa`/`structuredClone`/`parseTo` builtins, for std-module tables (collections, crypto, …), for native calls (`arity mismatch: native function '<name>' expects N arguments`, `src/sema/src/checks/type/native_check.cpp`), for `parallel.*` family calls, and for the network `next()` continuation.

## Minimal reproducer
```ts
// fails with CP3403
import console from "std/console";
function add(a: number, b: number): number { return a + b; }
console.log(`${add(1)}`);
```
`add` requires two parameters; one argument is given, so the call reports `arity mismatch: expected 2, got 1 argument`. The legal form supplies both arguments (or declares the second parameter optional). The pinned std flavor is `tests/cases/stdlib/02/parseint/parseint_arity_error` (`parseInt()` → `expects exactly 1 argument`); `tests/cases/functions-closures/03/spread/spread_call_middle_error` pins the trailing-spread rule.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3403` and spans the call.

## How to fix
1. Count the parameters against the call site: supply the missing arguments or drop the extras.
2. If the extra argument is genuinely optional, declare the parameter `name?: type` (or with a default) so the signature itself admits it.
3. For the spread case, move the spread to the final argument or convert it to its own variables.
4. For a std-module or native call, check the module's documented signature — many of these surfaces are intentionally exact-arity.
