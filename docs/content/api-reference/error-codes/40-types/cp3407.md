# CP3407 — Unknown type argument

**Stage:** semantic analysis — types · **Const:** `diagcode::kUnknownTypeArgument`

## What it means
A prefixed native type spelling (`r_'…'`, `c_'…'`, `ts_'…'`) names something that is not an allowed native value type — today: a raw pointer, reference, or array.

## Why it fires
Project type systems that are not TypeScript accept prefixed native spellings (`r_'i64'` for rust/cpp projects, `c_'int'`, `ts_'Date'`, …). `resolvePrefixedType` (`src/sema/src/checks/type/native_types.cpp`) rejects any prefixed name containing `*`, `&` or `[` with `raw pointer, reference, and array types are not permitted in <prefix>_'<name>'`. A prefixed name that is simply not a known native type reports CP3414 instead; this code is specifically for the illegal *shape* of the native spelling.

## Minimal reproducer
```ts
// fails with CP3407
let a: c_'int*' = 5;
```
`int*` is a raw pointer spelling, which prefixed types never permit, so the compiler reports `raw pointer, reference, and array types are not permitted in c_'int*'`. The legal spelling is a plain value type such as `c_'int'`. This exact case is pinned by `tests/cases/types/02/native/pointer/native_pointer_rejected`; `tests/cases/types/02/native/reference/native_reference_rejected` (`c_'int&'`) pins the same code for references.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3407` and spans the prefixed type.

## How to fix
1. Remove the `*`/`&`/`[]` suffix: prefixed types are plain value types (`c_'int'`, `r_'u64'`); cp3 has no raw pointer or reference spellings.
2. If you need a container, declare an array of the value type instead of `T[]` inside the prefix: write `r_'u32'[]` as an ordinary array annotation `u32[]` only where the type system accepts `u32` as a value type, or a typed array.
3. If the name you wanted was a native type the project does not support, check CP3414 — the native tier reports unsupported names there, not here.
