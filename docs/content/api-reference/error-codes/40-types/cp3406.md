# CP3406 — Invalid operand types

**Stage:** semantic analysis — types · **Const:** `diagcode::kInvalidOperandTypes`

## What it means
An operator is applied to an operand type it does not accept: a unary operator on a non-numeric type, an arithmetic or bitwise operator native values do not support, or an operand pair a comparison cannot accept.

## Why it fires
Unary operators (`src/sema/src/checks/expr/ops_check.cpp`): `invalid operand type '<T>' for unary '<op>'` — for example `+"5"`; the same slot reports the native `~` outside integers (`invalid operand type '<T>' for unary '~' (an integer type is required)`). The native tier (`src/sema/src/checks/type/native_types.cpp`) rejects `**` and `>>>` on native values (`the native type '<T>' has no '**' operator; convert it to number first`), and an integral-only operator (`%`, `&`, `|`, `^`, `<<`, `>>`) mixing a native value with a plain `number` (`the native operator '<op>' requires integral operands`). Binary comparisons reject incompatible operand pairs (`invalid operand types '<l>' and '<r>' for comparison`). For `instanceof`, the left side must be class-like (`invalid left operand of type '<T>' for 'instanceof'`); the right side must be a class name, which reports CP3401 otherwise.

## Minimal reproducer
```ts
// fails with CP3406
import console from "std/console";
console.log(+"5");
```
Unary `+` does not accept a string operand, so the compiler reports `invalid operand type 'string' for unary '+'`. This exact case is pinned by `tests/cases/operators/05/unary/unary_plus_string`; `tests/cases/types/02/native/power/native_power_rejected` pins the native `**` form.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3406` and spans the operand or operator.

## How to fix
1. Convert the operand deliberately: `parseTo(x, number)` / `parseTo(x, string)`, or arithmetic on a widened `number` instead of a native type.
2. For the integral-only operators, convert the plain `number` side explicitly (`parseTo(x, i64)`), or make both sides the same native type.
3. For `instanceof`, keep a class name on the right-hand side (not an arbitrary expression), and for comparisons, make both operands the same scalar kind.
