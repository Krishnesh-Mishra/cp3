# CP3421 — Unknown type banned

**Stage:** semantic analysis — types · **Const:** `diagcode::kUnknownTypeBanned`

## What it means
The retired `unknown` spelling was used as an annotation — a variable, parameter, return type, type alias, type argument, or any other annotation position.

## Why it fires
The `unknown` annotation spelling was retired with `void` (the same pass); an untyped value in cp3 is spelled `object`, and anything else takes the concrete type. Every annotation position names a real type node, so the check sits in `resolveNamedType` (`src/sema/src/checks/type/type_check.cpp`) and fires everywhere a `NamedType` is resolved, including nested positions (`Promise<unknown>`, `unknown[]`, union members). The diagnostic is `the 'unknown' type is removed; use a concrete type, or 'object' for an untyped value`. The spelling still resolves to the internal unknown sentinel, so misannotated programs continue to type-check permissively; only the spelling is illegal. The internal unknown sentinel (used to suppress error cascades) is unaffected.

## Minimal reproducer
```ts
// fails with CP3421
let x: unknown = 5;
```
`unknown` is a banned annotation spelling, so the declaration reports `the 'unknown' type is removed; use a concrete type, or 'object' for an untyped value`. The legal annotation is `object` for an untyped value, or a concrete type. This exact case is pinned by `tests/cases/types/05/unknown/unknown_ok`; `tests/cases/destructuring/rest_parameter_type_error` (`function collect(...items: unknown[])`) and `tests/cases/classes/04/diagnostics/field_unknown_error` pin the same code in parameter and field positions.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3421` and spans the banned annotation.

## How to fix
1. For an untyped payload, annotate `object` — the permissive spelling for “some value, shape unspecified.”
2. For anything else, write the concrete type: an interface, a class, a union, or `Map<string, V>`.
3. If you reached for `unknown` to mean “I don't care about this value,” `object` or an explicit concrete type is the supported replacement; `any` does not exist in cp3.
