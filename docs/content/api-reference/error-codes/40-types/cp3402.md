# CP3402 — Not assignable

**Stage:** semantic analysis — types · **Const:** `diagcode::kNotAssignable`

## What it means
A value is used where the position accepts nothing, or through a reference that may not hold anything: a `return <value>` in a function that returns nothing, or an un-narrowed read through a `weak` class field.

## Why it fires
Two check sites own this code today, both in semantic analysis. `analyzeReturn` (`src/sema/src/checks/stmt/stmt_check.cpp`) reports `a void function cannot return a value` when a function whose declared return type carries no value returns one. `inferMember` (`src/sema/src/checks/expr/member_check.cpp`) reports `value of a weak reference is possibly undefined; check it before use` when a member is read *through* an un-narrowed `weak` field — a weak reference may be collected, so its target cannot be touched until the read is proven safe by narrowing. The general "value of type X is not assignable to type Y" situation is CP3401, not this code; source-level `: undefined` functions route through the CP3401 path. No `tests/cases/` fixture pins this code.

## Minimal reproducer
```ts
// shape — verify against tests/cases/classes/03/weak/weak_parent_cycle
class Parent { child: Child; constructor(child: Child) { this.child = child; } }
class Child {
  weak parent: Parent | null;
  value: number;
  constructor(value: number) { this.value = value; this.parent = null; }
}
const c = new Child(1);
console.log(c.parent.child.value);
```
Reading `c.parent.child` without first narrowing `c.parent` (for example `if (c.parent !== null)`) is the un-narrowed weak read; the legal form narrows first, exactly as `tests/cases/classes/03/weak/weak_parent_cycle` does. The void-return form is not source-constructible in the current tree, since the `void` spelling is retired and `: undefined` routes through CP3401 — that half is verified only against `src/sema/src/checks/stmt/stmt_check.cpp`, not by a fixture.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3402` and spans the offending member access or return statement.

## How to fix
1. For the weak-reference form, narrow before the read: `if (c.parent !== null) { … }` (or `!== undefined` for a `weak x: T | undefined` field), the same form the weak-cycle fixtures use.
2. If narrowing is impossible at that point, copy the weak reference into a local and narrow the local instead.
3. For the return form, remove the value from `return` (a function declared to return nothing returns bare `return;` or nothing), or change its declared return type to one that carries the value.
