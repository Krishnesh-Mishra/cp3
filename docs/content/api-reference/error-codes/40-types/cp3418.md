# CP3418 — Invalid type argument

**Stage:** semantic analysis — types · **Const:** `diagcode::kInvalidTypeArgument`

## What it means
An explicit type-argument list has the wrong number of entries for the generic being instantiated — typically too many for a class or alias.

## Why it fires
Instantiation arities are checked at the naming site: `Array<T>` takes exactly one (`'Array' takes exactly one type argument; write 'Array<T>' or 'T[]'`); a type alias (`type alias '<name>' expects N type argument(s); got M`), a generic interface (`interface '<name>' expects N type argument(s); got M`), a user class (`class '<name>' expects N type argument(s); got M`) and the built-in utility types (`Partial requires exactly 1 type argument(s); got N`) all report this code (`src/sema/src/checks/type/type_check.cpp`). At a `new` expression, excess arguments against a generic class report `generic class '<name>' expects N type argument(s), got M` (`src/sema/src/checks/class/class_conform_check.cpp`), with the same wording repeated at emission (`src/codegen/src/emit/class/class_expr.cpp`). Note: a generic class with *missing* explicit arguments does **not** report this code — defaults fill from `= Y` defaults and then from `undefined`; this code is for lists with the wrong arity.

## Minimal reproducer
```ts
// fails with CP3418
import console from "std/console";
class Box<T> { value: T; }
const b = new Box<number, string>();
console.log("unreachable");
```
`Box` declares one type parameter; `new Box<number, string>()` supplies two, so the compiler reports `generic class 'Box' expects 1 type argument(s), got 2`. The legal spelling is `new Box<number>()`. This exact case is pinned by `tests/cases/classes/01/generic/generic_new_type_args_error`. Note: `new Map()` (a standard-library generic with no arguments) is a different situation — its own typed check reports CP3401 ("needs its type arguments"), pinned by `tests/cases/stdlib/02/map/missing/map_missing_type_args`.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3418` and spans the type-argument list.

## How to fix
1. Count the type parameters against the list: pass exactly the declared number, in order (`Box<number>`, `Record<string, number>`).
2. If arguments are missing, decide: supply them explicitly, or for a class whose parameters all carry `= Y` defaults, call `new Box()` and let the defaults fill in.
3. For `Array<T>`, prefer the shorthand `T[]` when one argument is all you need; `Partial`/`Pick`/`Omit` etc. take exactly their documented argument counts.
