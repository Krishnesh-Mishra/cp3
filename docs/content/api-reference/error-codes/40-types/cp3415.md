# CP3415 — Invalid condition

**Stage:** semantic analysis — types · **Const:** `diagcode::kInvalidCondition`

## What it means
A condition position (`if`, `while`, `for`, a conditional expression) is given an expression whose type carries no value at all — a void expression.

## Why it fires
`checkCondition` (`src/sema/src/checks/stmt/stmt_check.cpp`) runs on every condition and on none of them may the type be the internal `Void` sentinel: `invalid condition: a void expression is not a valid condition`. The sentinel arises when a call returns a function whose signature says it produces nothing — for example the documented `start()`/`stop()`/`reset()` members of a `Stopwatch`, typed as return-nothing. A condition on an ordinary `boolean`, a `number` (truthiness), a nullable or a union is fine. No `tests/cases/` fixture pins this code.

## Minimal reproducer
```ts
// shape — verify: no fixture pins CP3415; a void-typed call in a condition
// is the only source shape the Void sentinel reaches today.
import console from "std/console";
import time from "std/time";
const sw = time.stopwatch();
if (sw.start()) {
  console.log("tick");
}
```
`sw.start()` returns nothing (typed as a void call), so using it as the condition reports `invalid condition: a void expression is not a valid condition`. The legal spelling conditions on a value: `sw.start(); if (…) { … }` — or condition on a boolean expression of your own.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3415` and spans the condition expression.

## How to fix
1. Move the void call out of the condition position: run it as its own statement, then condition on the value you actually want.
2. If you meant to condition on the *result* of something, that something must return a value — check its declared return type; a function returning nothing cannot be truthy.
3. If the void call was a stand-in while drafting, replace it with the real condition (a comparison, a boolean variable).
