# CP3408 — Const reassignment

**Stage:** semantic analysis — types · **Const:** `diagcode::kConstReassignment`

## What it means
A `const` binding is being assigned to again — after declaration, via `++`/`--`, or in a compound assignment. `const` means exactly that: one binding, never rebound.

## Why it fires
During assignment checking (`src/sema/src/checks/expr/ops_check.cpp`), an assignment target that resolves to a `const` binding reports `cannot reassign to const '<name>'`; the same check fires in `inferUpdate` for `x++`/`x--` on a `const`. Note this is binding-level: a `const` object's *properties* are not covered by this code (mutating `const o = {…}; o.x = 1` is a property assignment, checked against the property's type, not a rebinding), and `const` on a typed-array value is equally protected — see the pinned fixture, which rebinds a `const a = new Int8Array(1)`.

## Minimal reproducer
```ts
// fails with CP3408
import console from "std/console";
const count = 1;
count = 2;
console.log(`${count}`);
```
`count` is a `const` binding, so the reassignment reports `cannot reassign to const 'count'`. The legal spelling changes the binding kind — `let count = 1; count = 2;` — or drops the reassignment. This exact case is pinned for a typed-array binding by `tests/cases/typed-arrays/03/typed/const/typed_const_rebind_error`.

## What happens
Compilation stops before code generation; nothing is produced. The diagnostic carries `CP3408` and spans the rebinding.

## How to fix
1. Change `const` to `let` if the value must change, or introduce a fresh binding instead of rebinding (`const count2 = count + 1;`).
2. For typed arrays and other handle values, mutate in place (`a[0] = x` where legal) instead of rebinding the handle.
3. If the reassignment is in a different scope from the declaration, double-check you are not shadowing by accident — the message names the binding that owns the `const`.
