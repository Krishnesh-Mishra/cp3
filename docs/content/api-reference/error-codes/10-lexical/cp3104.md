# CP3104 — Unterminated comment

**Stage:** lexer · **Const:** `diagcode::kUnterminatedComment`

## What it means
A block comment (`/* … */`) reached end of file without its closing `*/`. The rest of the file is inside the comment.

## Why it fires
The lexer's block-comment skipper scans for `*/` until end of file; line comments (`//`) are exempt because they end at the newline. If the closing delimiter never arrives, the diagnostic `unterminated block comment` is reported (`src/lexer/src/scanner.cpp`) and everything after `/*` is treated as comment text, swallowing the remainder of the file.

## Minimal reproducer
```ts
// fails with CP3104
const x = 1; /* this block comment never ends
console.log(x);
```
The comment opens on line 1 and never closes, so `console.log(x);` is comment text, not code. The diagnostic points at the opening `/*`. This case is not pinned by a `tests/cases/` fixture; the message is quoted from `src/lexer/src/scanner.cpp`.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3104` and spans the unterminated comment.

## How to fix
1. Close the comment with `*/`. Everything between `/*` and `*/` is ignored, so verify the file is not missing real code after an accidental `/*`.
2. If you wanted a line comment, use `//`: line comments need no terminator.
3. Beware `/*` inside a string or regex is just text — but a real `/*` in code starts a comment, so a typo like `/ *` vs `/*` is rarely the issue; a forgotten `*/` is.
