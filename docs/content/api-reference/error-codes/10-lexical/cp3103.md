# CP3103 — Unterminated template

**Stage:** lexer · **Const:** `diagcode::kUnterminatedTemplate`

## What it means
A template literal (backtick string) reached end of file before its closing backtick. The template never closes, so nothing after it can be scanned.

## Why it fires
The lexer scans a template chunk until the next backtick or the start of a `${ … }` interpolation. If a chunk ends at end of file, `unterminated template literal` is reported for the chunk (`src/lexer/src/templates.cpp`); if an interpolation never closes, the scan still ends inside template mode and the same code is reported at end of file (`src/lexer/src/scanner.cpp`). Unlike a raw newline in a regular string, backticks may contain newlines — the terminator must be a backtick, and it never arrives.

## Minimal reproducer
```ts
// fails with CP3103
const name = "sam";
const s = `hello ${name}
```
The closing backtick is missing: the template chunk (or the open interpolation) runs into end of file and the lexer reports `unterminated template literal`. The fix is to close the template with a backtick; everything after it, including `console.log(s);`, only scans once the template is closed.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3103` and points at the start of the unterminated chunk.

## How to fix
1. Add the missing closing backtick. If the template contains `${ … }`, make sure every interpolation is closed with `}` first.
2. If the template was meant to end earlier, check that you did not open a template inside a template comment or a nested interpolation by accident.
3. If you only needed a plain string on one line, a regular `"…"` literal avoids the issue entirely.
