# CP3102 — Unterminated string

**Stage:** lexer · **Const:** `diagcode::kUnterminatedString`

## What it means
A string literal reached a line break before its closing quote. CP3 strings do not span lines: the literal ends at the newline.

## Why it fires
The lexer scans a string until the matching quote or a raw line terminator. If a `\n`/`\r` arrives first, the scan stops there, the token is committed with an `unterminated` marker, and the diagnostic `unterminated string literal` is reported (`src/lexer/src/strings.cpp`). A backslash immediately before the newline is a line continuation and contributes nothing; a raw newline is not allowed.

## Minimal reproducer
```ts
// fails with CP3102
let s = "abc
";
```
The raw newline after `abc` ends the literal, so the closing quote on the next line is now a stray token of its own. The legal spelling is a template literal, a backslash-newline line continuation, or the string kept on one line.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3102` and points at the literal.

## How to fix
1. Close the string on the same line, or split it with explicit concatenation (`"abc" + "def"`).
2. For multi-line text, use a template literal (backticks), which may contain raw newlines — see CP3103.
3. For a line continuation, make sure the `\` is the last character before the newline and inside the string, not stray punctuation outside it.
