# CP3101 — Invalid character

**Stage:** lexer · **Const:** `diagcode::kInvalidCharacter`

## What it means
The lexer met a byte it cannot turn into any token. The file is not lexable as CP3 as written; the offending character is named in the message.

## Why it fires
During scanning, a character with no token form is rejected in place rather than skipped: a bare `#` that is not a private identifier (`unexpected character '#'`), a `\` outside a string or template literal (`unexpected '\' outside a string or template literal`), and any other byte the scanner cannot classify (`unexpected character '<c>'`). The scanner consumes one byte and recovers, so later diagnostics may be noisier than usual.

## Minimal reproducer
```ts
// fails with CP3101
let x = \ 5;
```
The backslash cannot open a token here, so the lexer reports `unexpected '\' outside a string or template literal`. The legal form is a string escape (`"\\"`) or no backslash at all. This case is not pinned by a `tests/cases/` fixture; the scanner messages are quoted from `src/lexer/src/`.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3101` and the span of the offending character.

## How to fix
1. Delete or replace the character; if it belongs in a string, put it inside quotes and use a valid escape (see CP3106).
2. If the character looks like it should be text, put it inside a string literal. Identifier bytes are ASCII letters, `_`, `$`, digits (after the first) and UTF-8 bytes ≥ 0x80; anything else has no token form.
3. For a stray `#`, remember private class fields spell `#name` only inside class bodies; a bare `#` has no meaning elsewhere.
