# CP3105 — Invalid numeric literal

**Stage:** lexer · **Const:** `diagcode::kInvalidNumericLiteral`

## What it means
A numeric literal is malformed: a digit that does not belong to the indicated radix, a separator in an illegal place, a missing digit run, or a legacy octal form.

## Why it fires
The lexer validates numbers as it scans them. For `0x`/`0b`/`0o` forms, a digit outside the radix, or an identifier character immediately following the literal (`0b12`, `0x1Fg`), marks it malformed; an empty digit run and an illegal `_` separator do the same. A legacy leading-zero form (`08`) is rejected outright — cp3 has no implicit octal. The diagnostic is `invalid numeric literal` (`src/lexer/src/numbers.cpp`).

## Minimal reproducer
```ts
// fails with CP3105
let flags = 0b12;
```
`2` is not a binary digit, so the literal is malformed and the lexer reports `invalid numeric literal`. The legal spelling is `0b10` (or decimal `2`). This case is not pinned by a `tests/cases/` fixture; the message is quoted from `src/lexer/src/numbers.cpp`. Note `1.2.3` is not this code — the trailing `.3` lexes as member access and fails later in the parser.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3105` and spans the literal.

## How to fix
1. Fix the digits for the radix: `0b` admits only `0`/`1`, `0o` only `0`–`7`, `0x` only hex.
2. Use `_` only between digits (`1_000_000`), never leading, trailing or doubled, and never adjacent to the radix prefix's first digit in a way that empties the run.
3. Write legacy octal as explicit `0oNNN`; `08`/`09`/`0_1` are always errors.
