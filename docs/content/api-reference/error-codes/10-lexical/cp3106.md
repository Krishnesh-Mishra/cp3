# CP3106 — Invalid escape

**Stage:** lexer · **Const:** `diagcode::kInvalidEscape`

## What it means
A string or template literal contains an escape sequence the lexer cannot decode: an unknown escape character, a short or malformed `\xHH`/`\uXXXX`, a broken `\u{…}`, or a legacy octal escape.

## Why it fires
Escapes are decoded while the literal is scanned (`src/lexer/src/strings.cpp`), and each malformed shape reports this code: `invalid escape sequence`, `invalid escape sequence at end of file`, `invalid hexadecimal escape sequence`, `invalid Unicode escape sequence`, and `legacy octal escape sequences are not allowed` (for `\1`–`\9` and `\0` followed by a digit). The lexer recovers by emitting the offending byte, so the rest of the literal still scans but the value is unreliable — the file does not compile.

## Minimal reproducer
```ts
// fails with CP3106
const s = "100\q";
```
`\q` is not a known escape, so the lexer reports `invalid escape sequence`. The legal spelling for a literal backslash is `"100\\q"`; for a genuine escape use one of `\n`, `\t`, `\r`, `\b`, `\f`, `\v`, `\0`, `\\`, `\'`, `\"`, `\xHH`, `\uXXXX` or `\u{1F600}`. This case is not pinned by a `tests/cases/` fixture; the messages are quoted from `src/lexer/src/strings.cpp`.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3106` and spans the offending escape.

## How to fix
1. If you wanted a literal backslash, double it (`\\`).
2. Check `\x` (exactly two hex digits) and `\u` (exactly four hex digits, or `\u{…}` with a hex scalar value ≤ 0x10FFFF); pad with zeros as needed.
3. Replace legacy octal escapes (`\0`–`\9` style) with `\xNN` or the intended code point; they are never valid in cp3.
