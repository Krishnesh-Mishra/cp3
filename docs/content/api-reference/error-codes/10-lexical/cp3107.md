# CP3107 — Invalid regular expression

**Stage:** lexer · **Const:** `diagcode::kInvalidRegExp`

## What it means
A regular expression literal (`/…/flags`) is malformed: the pattern never closed, or a flag is not in the documented set or is duplicated.

## Why it fires
The lexer scans the pattern until the closing `/` (a regex cannot span lines) and validates the flags it finds (`src/lexer/src/regexp.cpp`). An unterminated pattern reports `unterminated regular expression literal`. Each flag must be one of `d`, `g`, `i`, `m`, `s`, `u`, `v`, `y`; an unknown one reports `invalid regular expression flag '<c>'`, and a repeated one reports `duplicate regular expression flag '<c>'`. Pattern-validity problems beyond the flags are a separate concern handled by sema.

## Minimal reproducer
```ts
// fails with CP3107
let r = /ab
```
The pattern is never closed on the line, so the lexer reports `unterminated regular expression literal`. The legal form is a complete literal, for example `/ab/i`. This exact case is pinned by `tests/cases/regex/01/regex_invalid_pattern`; `tests/cases/regex/01/regex_duplicate_flag` and `tests/cases/regex/02/regex_unknown_flag` pin the flag messages.

## What happens
Compilation stops before parsing; nothing is produced. The diagnostic carries `CP3107` and spans the offending part of the literal.

## How to fix
1. Close the pattern with a `/` on the same line.
2. Remove or replace the offending flag: only `d g i m s u v y` are documented; delete any other letter.
3. Remove the duplicate flag — one occurrence of each flag is all a regex takes.
