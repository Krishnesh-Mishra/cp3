# CP3504 — Missing return

**Stage:** semantic analysis — statements · **Const:** `diagcode::kMissingReturn`

## What it means
A function (or method) is declared to return a value, but at least one control-flow path falls off the end of its body without returning anything.

## Why it fires
Checked at the end of the statement pass of semantic analysis (and for methods, at the end of method checking): the declared return type is compared against the paths that reach the end of the body. The diagnostic reports `function '<name>' is declared to return a value but may fall off the end of its body` (methods use the same wording with `method` in place of `function`).

## Minimal reproducer
```ts
// fails with CP3504
import console from "std/console";
function f(x: number): number {
  if (x > 0) {
    return 1;
  }
}
console.log(f(0));
```
The legal form returns on every path, or widens the declared return to include the missing case (e.g. `number | undefined`). Pinned by `tests/cases/functions-closures/02/missing/missing_return_if_no_else`, `missing_return_switch_no_default` and `missing_return_switch_default_break`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Add a `return` on the path that falls off the end.
2. If falling off the end is intentional, change the declared return type to `undefined` or a union that includes it (`number | undefined`).
3. If the function can never reach the end (all paths throw), that is fine — the check passes; no change needed.
