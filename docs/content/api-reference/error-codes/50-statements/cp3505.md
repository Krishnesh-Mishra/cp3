# CP3505 — Unreachable code

**Stage:** semantic analysis — statements · **Const:** `diagcode::kUnreachableCode`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for the statement that can never execute — for example, statements after a `return` or `throw`. The compiler does not diagnose unreachable code today.

## Why it fires
Never, in this tree: `diagcode::kUnreachableCode` is declared in the code table but has no emission site anywhere in `src/`, and no test pins it. The only reachability machinery in this area (`allPathsReturn`) is used for CP3504 (missing return), not to diagnose unreachable statements. If the check is wired up later, it belongs in the statement pass of semantic analysis.

## Minimal reproducer
```ts
// shape — reserved code; nothing fails with CP3505 in this build
import console from "std/console";
function f(): number {
  return 1;
  console.log("unreached");
}
console.log(f());
```
The canonical situation is a statement after an unconditional `return`/`throw` in the same block. Writing it today produces no diagnostic; it compiles and simply runs the reachable prefix.

## What happens
Nothing — the code is never emitted. A program with unreachable statements compiles and runs.

## How to fix
1. Nothing to fix on the diagnostics side; delete the dead statements if you find them.
2. If unreachable code should be a hard error in your project, enforce it in review or linting.
3. If you believe you have seen CP3505 from a build, please report it with a reproducer — no emission site exists.
