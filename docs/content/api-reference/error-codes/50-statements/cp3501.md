# CP3501 — Return outside a function

**Stage:** semantic analysis — statements · **Const:** `diagcode::kReturnOutsideFunction`

## What it means
The compiler found a `return` statement that is not inside any function body. CP3 has no top-level `return`, so the statement has no function to return from.

## Why it fires
Checked in the statement pass of semantic analysis, which tracks whether each statement sits inside a function. The diagnostic anchors on the `return` itself and is reported before any typing of the surrounding function happens.

## Minimal reproducer
```ts
// fails with CP3501
return 1;
```
The legal form returns from a function body: `function f(): number { return 1; }`. Any `return` written at the top level of a module, or inside a non-function body, trips the check. No conformance fixture pins CP3501 in this tree; the shape mirrors the statement-level check in `src/sema/src/checks/stmt/stmt_check.cpp`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Move the `return` into the function it belongs to, or delete it.
2. If the module needs a value at the top level, assign it to a binding (`const value = ...`) or wrap the logic in a function and call it.
3. If the code was meant to exit the process, call the std library's exit path instead of `return`.
