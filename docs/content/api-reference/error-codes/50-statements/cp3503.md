# CP3503 — Continue outside a loop

**Stage:** semantic analysis — statements · **Const:** `diagcode::kContinueOutsideLoop`

## What it means
The compiler found a `continue` statement that is not inside a loop. Unlike `break`, `continue` is only meaningful as "start the next iteration", so it is rejected even inside a `switch`.

## Why it fires
Checked in the statement pass of semantic analysis via the current loop nesting depth (switch does not count). The diagnostic reports `continue outside of a loop` and anchors on the `continue` statement.

## Minimal reproducer
```ts
// fails with CP3503
import console from "std/console";
for (let i = 0; i < 3; i = i + 1) {
  const step = (): undefined => {
    continue;
  };
  step();
}
```
The legal form places `continue` directly in a loop body; a function or arrow between the `continue` and the loop breaks the link, because the body of that function is not the loop body. Pinned by `tests/cases/control-flow/01/continue/continue_in_arrow_in_loop` and `tests/cases/control-flow/01/continue/continue_in_method_in_loop`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Move the `continue` back into the loop body, at the top level of it (not inside a nested function).
2. If you need to bail out of the enclosing loop from a nested function, return a sentinel/flag from that function and `continue` in the loop body.
3. If you meant to leave a `switch`, use `break` instead (allowed there).
