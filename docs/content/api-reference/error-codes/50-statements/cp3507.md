# CP3507 — Missing destructuring initializer

**Stage:** semantic analysis — statements · **Const:** `diagcode::kMissingDestructuringInit`

## What it means
A declaration uses a destructuring pattern (`let [a, b]` / `let { x }`) without an initializer. There is no value to destructure, so the binding cannot be formed.

## Why it fires
Checked where the declaration is processed; a destructuring pattern with no initializer has no source to pull values from. The only emission site in this tree is the back end's repeat diagnostic (`a destructuring declaration needs an initializer`, `src/codegen/src/emit/pattern/patterns.cpp`), kept so a codegen-only pass stays honest.

## Minimal reproducer
```ts
// fails with CP3507
import console from "std/console";
function g(): undefined {
  let { a, b };
  console.log("x");
}
g();
```
The legal form always carries an initializer: `let { a, b } = source;` or `const [a, b] = source;`. Pinned by `tests/cases/functions-closures/02/destructure/destructure_no_initializer_error`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code. (The diagnostic is also reported by the back end as a build-time error with the same code.)

## How to fix
1. Give the destructuring declaration an initializer — the value to destructure (e.g. `let { a, b } = pair;`).
2. If the value is not available yet, split the declaration: `let a: number; let b: number;` and assign in branches or a constructor.
3. For parameters, use a default value (`({ a, b } = fallback)`) so the pattern always has something to bind.
