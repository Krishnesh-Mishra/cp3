# CP3508 — Continue with a non-iteration label

**Stage:** semantic analysis — statements · **Const:** `diagcode::kContinueNonIterationLabel`

## What it means
A labeled `continue` names a label, but the labeled statement is not an iteration statement. `continue` means "start the next iteration", and a label on anything else gives it nothing to iterate.

## Why it fires
Checked in the statement pass of semantic analysis, which resolves labels against the statements they name. The diagnostic reports `continue label '<label>' does not denote an iteration statement`. A label on a block or a `switch` may only be broken out of — use `break <label>;` there instead.

## Minimal reproducer
```ts
// fails with CP3508
import console from "std/console";
block: {
  continue block;
}
```
The legal form puts the label on a loop (`outer: for (...) { ... continue outer; }`), or uses `break block;` to leave a labeled block. Pinned by `tests/cases/control-flow/01/continue/continue_to_block_label`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. If the labeled statement is a loop you meant to skip an iteration of, keep `continue <label>` and make sure the label is on the loop itself.
2. If it is a block or a `switch`, use `break <label>;` — leaving is allowed, continuing is not.
3. If you meant to restart an outer loop from inside a nested one, label the outer loop and `continue <outer-label>;`.
