# CP3502 — Break outside a loop

**Stage:** semantic analysis — statements · **Const:** `diagcode::kBreakOutsideLoop`

## What it means
The compiler found a `break` statement that is not inside a loop or a `switch`. A `break` is only meaningful as "leave this enclosing statement", and there is nothing to leave here.

## Why it fires
Checked in the statement pass of semantic analysis via the current loop/switch nesting depth. The diagnostic reports `break outside of a loop or switch` and anchors on the `break` statement.

## Minimal reproducer
```ts
// fails with CP3502
import console from "std/console";
break;
console.log("done");
```
The legal form places `break` inside a loop or a `switch` (case arms may `break` out). A bare `break` at the top level of a module, or inside a function with no enclosing loop/switch, trips the check. Pinned by `tests/cases/v0-2-2/break_outside_loop` and `tests/cases/control-flow/01/_ambiguous/break/break_outside_loop`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Move the `break` inside the loop or `switch` it should exit.
2. If you meant to exit a function, use `return` instead.
3. If you meant to skip to the next iteration, use `continue` (which carries its own check, CP3503).
