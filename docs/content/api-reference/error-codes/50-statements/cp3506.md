# CP3506 — Await outside an async function

**Stage:** semantic analysis — statements · **Const:** `diagcode::kAwaitOutsideAsync`

## What it means
The compiler found an `await` in a context that has no coroutine to suspend: a plain function, a non-async arrow, or any non-async body.

## Why it fires
Checked in the expression pass of semantic analysis, which records whether the enclosing function is `async`. The diagnostic reports `'await' is only allowed in an async function or at the top level`. An `await` at the top level of a module is allowed; the error is for `await` inside a non-async function body.

## Minimal reproducer
```ts
// fails with CP3506
import console from "std/console";
async function g(): Promise<number> { return 7; }
function f(): number {
  let v = await g();
  return v;
}
console.log(`${f()}`);
```
The legal form declares the enclosing function `async` (`async function f(): Promise<number>`) or moves the `await` to the top level. Pinned by `tests/cases/async/01/await/await_outside_async_error`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Mark the enclosing function or arrow `async`, and let its return type become `Promise<...>` (an annotated `Promise<number>` is usually what you want).
2. If the function cannot be `async`, await at the top level of the module, or restructure into an `async` entry point.
3. If the callee is not actually async, drop the `await` (over-`await`ing a plain value is legal and does nothing).
