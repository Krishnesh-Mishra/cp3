# CP3509 — Throw of a non-Error value

**Stage:** semantic analysis — statements · **Const:** `diagcode::kThrowNonError`

## What it means
The compiler found a `throw` whose value is not an `Error` (or a subclass of `Error`). TypeScript allows throwing any value, but CP3 does not.

## Why it fires
Checked in the statement pass of semantic analysis, which infers the type of the thrown expression. The diagnostic reports `TypeScript allows throwing any value, but CP3 only allows Error objects (Error or a subclass). CP3 rejects throwing '<type>' because a catch binds one static Error handle: there is no runtime metadata or hidden boxing in the native output. Construct an Error (or a subclass) and throw that instead.` — a catch binds exactly one static `Error` handle, so nothing else would be catchable in a typed way.

## Minimal reproducer
```ts
// fails with CP3509
import console from "std/console";
try { throw "boom"; } catch (e) { console.log(e); }
```
The legal form throws an `Error` (or subclass): `throw new Error("boom")`. Pinned by `tests/cases/errors/01/catch/catch_thrown_string` and `tests/cases/errors/01/catch/catch_thrown_number`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Construct an `Error` (or one of its subclasses, such as `TypeError`) and throw it: `throw new Error("boom")`.
2. Carry structured data as fields on a subclass — CP3 has no room for arbitrary thrown values, so "throw an object literal" is not available.
3. If the failure is expected and routine, return a result/union type instead of throwing.
