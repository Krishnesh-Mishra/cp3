# CP3511 — Package entry exports nothing

**Stage:** semantic analysis — statements (warning) · **Const:** `diagcode::kPackageNoExports`

## What it means
A `type: package` project whose entry module exports nothing produces no public surface, so the package is useless to its importers. This is a warning, not an error.

## Why it fires
Reported by the `cp3 check` pipeline on the package entry after the program is analyzed (a package-project entry whose export surface is empty). The diagnostic reports `package entry module exports nothing: the package produces no public surface. Add an exported function/class/type or set 'type': 'application'.` If the package is meant for internal/binary use, the `application` type is the right spelling instead.

## Minimal reproducer
```ts
// warns with CP3511
// package.json: { "type": "package", "main": "src/index.cp3" }
function helper(): number { return 1; } // not exported
```
The legal form exports something (`export function helper(...) { ... }`) or sets `"type": "application"` in `package.json`. No conformance fixture pins CP3511 in this tree; the shape follows the `packageEntryExports` check in the `cp3 check` pipeline.

## What happens
Compilation continues; the diagnostic carries the code as a warning. The package builds, but its public surface is empty.

## How to fix
1. Export the intended API from the entry module: `export function`, `export class`, `export type`/`interface`, or `export { ... }`.
2. If the package is an application and not a library, set `"type": "application"` in `package.json` instead.
3. If the entry is a re-export hub, use explicit `export ... from "./module"` lines; an entry with only private declarations still warns.
