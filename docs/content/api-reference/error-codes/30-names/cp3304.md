# CP3304 — Unresolved import

**Stage:** semantic analysis — names · **Const:** `diagcode::kUnresolvedImport`

## What it means
An import names something the target module does not provide: a named binding that does not exist, or a use whose import form has no supported lowering.

## Why it fires
During module resolution, a named import whose specifier is absent from the module's export surface reports `module '<module>' does not export '<name>'` (`src/modules/src/support/export_surface.cpp`) — for default-only std modules such as `std/console` it appends a `use the default import: …` hint instead of the usual suggestions list. At the emission stage, a use of a namespace import (`import * as ns from …`) has no C++ lowering and reports `unresolved import: <why>` (`src/codegen/src/emit/expr/expr.cpp`, `src/codegen/src/emit/call/call_args.cpp`) — for example calling a type-only export as a value. The module specifier itself missing is CP3601/CP3602, a different code.

## Minimal reproducer
```ts
// fails with CP3304
import { console } from "std/console";
console.log("x");
```
`std/console` has no named export `console` — its surface is a default export, so the compiler reports `module 'std/console' does not export 'console'; use the default import: import console from "std/console";`. This exact case is pinned by `tests/cases/diagnostics/wrong_named_import`.

## What happens
Compilation stops; nothing is produced. The diagnostic carries `CP3304` and points at the importing declaration (or, for the emission-stage form, at the offending use site).

## How to fix
1. Use the import shape the module documents: std modules with a default export take `import console from "std/console"`, not a named form.
2. For a wrong specifier, check `did you mean '<name>'?` and the listed named exports in the message; the compiler prints candidate names.
3. For a namespace import with no lowering, import the specific members you use instead of the namespace object, or switch the module to a type-only use where the module is type-only.

## Related codes
- CP3301 — Undefined identifier (the binding that fails later, not the import)
- CP3302 — Undefined type (the same failure in type-annotation position)
- CP3305 — Member not found (the import resolved; the member did not)
