# CP3303 — Duplicate declaration

**Stage:** semantic analysis — names · **Const:** `diagcode::kDuplicateDeclaration`

## What it means
The same name is declared twice in the same scope in a way that is not an allowed overload. One of the two declarations does not take effect as written.

## Why it fires
Scope building (`src/sema/src/support/scopes.cpp`) rejects a second binding for an existing name with `duplicate declaration of '<name>'` — the exceptions are a hoisted `var` replacing its own placeholder and function-overload sets, which merge instead of conflicting. The same code is reported for a second index signature in an interface or object type (`at most one index signature per interface or object type`, `src/sema/src/checks/type/type_check.cpp`) and, at emission, for a function-local enum whose name is already taken (`duplicate enum name '<name>' (the enum declarations of a unit share one namespace scope)`, `src/codegen/src/emit/decl/decl.cpp`).

## Minimal reproducer
```ts
// fails with CP3303
let a = 1;
let a = 2;
```
`a` is bound twice in the same scope; the second binding is rejected: `duplicate declaration of 'a'`. The legal form is one declaration per name — rename one of them, or merge the initializers. This case is not pinned by a `tests/cases/` fixture; the sema path is quoted from `src/sema/src/support/scopes.cpp`.

## What happens
Compilation stops before code generation; nothing is produced. The diagnostic carries `CP3303` and spans the duplicate declaration.

## How to fix
1. Rename one of the declarations, or remove the redundant one.
2. If the two declarations are both functions with the same name, they already form an overload set — do nothing; overloads are legal.
3. If the conflict is two index signatures in one interface or object type, merge them into a single signature with a union value type (`{ [key: string]: string | number }`).
