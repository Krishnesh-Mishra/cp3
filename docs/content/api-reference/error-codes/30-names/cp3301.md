# CP3301 — Undefined identifier

**Stage:** semantic analysis — names · **Const:** `diagcode::kUndefinedIdentifier`

## What it means
A name used as a value does not resolve to any binding visible at that point. The compiler cannot know what the identifier refers to.

## Why it fires
During name resolution (`src/sema/src/semantic_analyzer.cpp`, `reportUndefinedName`): an identifier in expression position with no declaration, parameter, import or builtin in scope reports `cannot find name '<name>'`. When a close spelling is visible it appends a `did you mean '<candidate>'?` suggestion; when the name is a std-module builtin used without its import it appends the exact import statement to add (for example `import Math from "std/math";`) instead of just the bare message. The same check backs `super` outside a derived class and an unresolved name in assignment position.

## Minimal reproducer
```ts
// fails with CP3301
import console from "std/console";
let message = "hi";
console.log(massage);
```
`massage` has no binding; the nearest visible name is `message`, so the diagnostic suggests it: `cannot find name 'massage'; did you mean 'message'?` This exact case is pinned by `tests/cases/diagnostics/unknown_identifier_suggestion`. `tests/cases/diagnostics/std_module_import_hint` pins the import-hint form for `Math` without `import Math from "std/math";`.

## What happens
Compilation stops before type checking; nothing is produced. The diagnostic carries `CP3301` and spans the identifier, with a suggestion when one exists.

## How to fix
1. Fix the spelling — check the suggestion if one is printed; the wrong name is usually a transposition of a nearby binding.
2. Declare or import the binding: a missing `import console from "std/console";` is the most common cause for std builtins (the compiler hands you the exact import line to add).
3. Check scope: a name declared inside another function or block is not visible here. For class-member uses that report instead of failing, see CP3305.

## Related codes
- CP3302 — Undefined type (the same situation in type-annotation position)
- CP3304 — Unresolved import (the import itself exists but does not provide the name)
- CP3305 — Member not found (the object resolves, the member does not)
