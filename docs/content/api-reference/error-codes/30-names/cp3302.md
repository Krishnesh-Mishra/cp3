# CP3302 — Undefined type

**Stage:** semantic analysis — names · **Const:** `diagcode::kUndefinedType`

## What it means
A type annotation names a type the compiler cannot resolve. The annotation resolves to an unknown sentinel, so the position it annotates carries no type information.

## Why it fires
While resolving a named type (`resolveNamedType`, `src/sema/src/checks/type/type_check.cpp`): after the primitive lookup, the generic instantiation machinery (aliases, interfaces, classes) and the native tier, a name that is still unknown reports `cannot find type name '<name>'`. The check applies in every annotation position — variable, parameter, return type, type alias, type argument. Note the precedence: an unsupported native spelling such as `r_'i128'` or `r_'str'` reports CP3414 instead, with the native-tier message, not this one.

## Minimal reproducer
```ts
// fails with CP3302
let x: Frobnicate = 1;
```
`Frobnicate` is not declared, imported, or a primitive/generic the compiler knows, so the annotation reports `cannot find type name 'Frobnicate'`. The legal form names a declared interface/class/alias, a primitive (`number`, `string`, …) or a generic instantiation (`Array<string>`). This case is not pinned by a `tests/cases/` fixture; the rule and message are quoted from `src/sema/src/checks/type/type_check.cpp`.

## What happens
Compilation stops before code generation; nothing is produced. The diagnostic carries `CP3302`; dependent positions fall back to a permissive unknown so the same mistake is not re-reported at every use.

## How to fix
1. Fix the spelling. If the type is declared in this project, the import or the name itself is usually what is missing.
2. Declare the type (`interface`/`class`/`type`) before the annotation that uses it, or import it.
3. If you meant a native project type spelling, check the project's `typeSystem` — `r_'…'` / `c_'…'` names are only meaningful with the rust/cpp type systems, and an unsupported native name reports CP3414, not this code.
