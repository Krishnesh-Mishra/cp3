# CP3901 — Parallel shared mutation

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kParallelSharedMutation`

## What it means
An indexed write inside a `parallel.*` closure targets captured (shared) state, and the index is not `parallel.for`'s own induction variable — so the compiler cannot prove the writes are disjoint and they would race.

## Why it fires
Checked by the capture-safety scan of semantic analysis, which walks every `parallel.*` closure body and flags writes through it (`src/sema/src/checks/stmt/parallel_check.cpp` + `parallel_expr_check.cpp`). The diagnostic reports `unsafe indexed write to captured state inside a parallel.* closure: only parallel.for's own induction variable is allowed as the index (a computed index cannot be proven disjoint)`.

## Minimal reproducer
```ts
// fails with CP3901
let a = [1, 2, 3];
let j = 1;
parallel.for(0..a.length, (i) => { a[j] = 0; });
```
The legal form indexes captured state with the induction variable only (`a[i] = 0;` with `i` from the same `parallel.for`), or returns values and combines them on the calling thread. Pinned by `tests/cases/concurrency/parallel/computed/parallel_computed_index_write` (placeholder code, `contains: "index"`) and `parallel_run_index_write_not_parallel_for`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Index the captured array with the `parallel.for` induction variable (`a[i] = v`) — that is the one write the compiler can prove disjoint.
2. Otherwise, do not write to captured arrays from parallel closures: return the per-element values and store them on the calling thread, or fold with `parallel.reduce`.
3. If the shared structure is genuinely needed, restructure around `Map`/`Set` reads on the calling thread, or use a worker with explicit message passing.
