# CP3916 — Worker module binding

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kWorkerModuleForm`

## What it means
A worker unit (`worker.cp3`) declares a module-level binding whose type has no value spelling — a handle, a promise, a function, or anything else that cannot be stored in the worker's `thread_local` state.

## Why it fires
Checked when the worker unit's module bindings are emitted (`src/codegen/src/emit/worker/worker_module.cpp`): each `const`/`let` binding at the top level of the worker unit is classified, and a binding that is not representable as a value reports `this worker module binding has no value spelling in a worker unit (its type is '<label>')`. Worker module state lives in the worker thread's own `thread_local` slot, which needs a value representation.

## Minimal reproducer
```ts
// worker.cp3 — fails with CP3916
const handler = (n: number): number => n + 1;

export default (thread: Thread<number, number>) => {
  thread.on("message", (n) => {
    thread.postMessage(handler(n));
  });
};
```
The legal form binds only value-representable module state in a worker unit (`const factor: number = 2;`), or computes non-value values inside the entry body instead. No conformance fixture pins CP3916 in this tree; the shape follows the module-binding lowering in `worker_module.cpp`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Replace non-value module bindings with value types: numbers, strings, booleans, arrays, records, enums, or unions/options of those.
2. Move the initialization into the entry arrow (`export default (thread: ...) => { ... }`) — locals there have no value-spelling requirement at module scope (they are ordinary locals of the entry function).
3. If the value is needed as shared state for message handlers, keep it as a plain record and rebuild it on each message.
