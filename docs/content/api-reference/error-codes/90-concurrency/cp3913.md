# CP3913 — Parallel accumulator type

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kParallelAccumulatorType`

## What it means
The initial value of a `parallel.reduce` is not a copyable cp3 value type — a class instance, a handle, a promise, a function, or any aggregate carrying one of those. The accumulator is copied once per element, so it must be an ordinary value.

## Why it fires
Reported when the reduction is lowered: the accumulator's type is checked for representability (`src/codegen/src/emit/misc/parallel.cpp`). The diagnostic reports `a parallel.reduce accumulator must be a cp3 value type (a number, string, boolean, array, record, enum, or a union of those), not '<label>'`. (The code comment says sema reports the same rule; in this tree the emission is in the back end.)

## Minimal reproducer
```ts
// fails with CP3913
import console from "std/console";

class Counter {
  value: number = 0;
}

let c = parallel.reduce(0..3, new Counter(), (acc, i) => acc);
console.log("unreachable");
```
The legal form starts the reduction with a value type — `parallel.reduce(0..3, 0, (acc, i) => acc + i)`. Pinned by `tests/cases/concurrency/parallel/reduce/non/parallel_reduce_non_value_accumulator`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Start the accumulator with a value type: `0`, `""`, `false`, an array, a record of value fields, an enum, or a union of those.
2. If you need a rich accumulator, keep it as a plain record of value fields and rebuild it inside the closure body (`(acc, i) => ({ ...acc, total: acc.total + i })`).
3. If the work genuinely needs shared mutable state, use a worker with typed messages instead of `parallel.reduce`.
