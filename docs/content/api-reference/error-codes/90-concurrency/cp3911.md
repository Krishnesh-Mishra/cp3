# CP3911 — Worker handle member

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kWorkerHandleMember`

## What it means
Something was used on a worker handle (`w` or `thread`) that is not part of the handle's surface, or the handle was used with the wrong arity/arguments/events, or `new Worker(...)` was given type arguments.

## Why it fires
Checked when the handle member call is lowered (`src/codegen/src/emit/worker/worker_handles.cpp` and `worker.cpp`). Messages seen: `this member is not part of the worker handle surface (main: postMessage / on / request / terminate; worker: on / postMessage)`, `new Worker(...) does not take type arguments; the worker entry's Thread<In, Out> annotation is the single source of truth`, `worker handle calls do not take type arguments`, `on(event, listener) takes a literal "message" or "error" and an inline arrow listener`, `the worker event must be "message" or "error"`, `postMessage(...) takes exactly one message value`, `terminate() takes no arguments` — the surface is deliberately small.

## Minimal reproducer
```ts
// fails with CP3911
const w = new Worker("./worker_impl.cp3");
w.bogus(1);
w.terminate();
```
The legal form uses only the handle surface: main side `postMessage(v)`, `on("message"|"error", l)`, `await w.request(v)`, `terminate()`; worker side `on(...)`, `postMessage(v)`. No conformance fixture pins CP3911 in this tree; the shape follows the handle lowering in `worker_handles.cpp` (e.g. a `w.bogus(...)` call, or `new Worker<TypeArgs>(...)`).

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Use a member of the handle surface: main side `postMessage`, `on`, `request`, `terminate`; worker side `on`, `postMessage`.
2. Drop type arguments on `new Worker(...)` — the `Thread<In, Out>` annotation is the channel's single source of truth.
3. Fix the event name to `"message"` or `"error"`, pass exactly one message value, and give listeners inline arrows.
