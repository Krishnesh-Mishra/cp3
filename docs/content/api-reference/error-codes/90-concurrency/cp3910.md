# CP3910 — Worker path is computed

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kWorkerComputedPath`

## What it means
`new Worker(...)` is called with something other than one static `.cp3` path literal or one inline arrow. The compiler must know the worker's compilation unit at compile time, so a computed path cannot work.

## Why it fires
Reported in the worker handling of codegen (`src/codegen/src/emit/worker/worker.cpp`) when the call does not match the expected shape: `new Worker(...) takes one static `.cp3` path or one inline `(thread: Thread<In, Out>) => ...` arrow`, or, when the argument is not an inline arrow, `the worker file path must be a static string literal naming a `.cp3` file (a computed path is not a compile-time unit)`.

## Minimal reproducer
```ts
// fails with CP3910
const p = "./worker_shape_impl.cp3";
const w = new Worker(p);
w.terminate();
```
The legal form passes the literal directly (`new Worker("./worker_shape_impl.cp3")`) or an inline arrow. Pinned by `tests/cases/concurrency/worker/computed/worker_computed_path` and `tests/cases/concurrency/worker/check/worker_check_computed_path`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Inline the path literal at the call site — computed paths are not available, by design.
2. If the path depends on configuration, select among a fixed set of literals (`const p = isProd ? "./prod.cp3" : "./dev.cp3";` is still not allowed — write the `new Worker(...)` at each branch).
3. If the decision is dynamic for real, use the inline-arrow form, which needs no path at all.
