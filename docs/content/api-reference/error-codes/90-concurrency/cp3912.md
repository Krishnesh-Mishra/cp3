# CP3912 — Parallel closure shape

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kParallelClosureShape`

## What it means
A closure passed to `parallel.*` cannot be shaped the way `parallel.*` runs it: an `async` closure has no event loop on a pool thread, and a `parallel.run()` closure takes no parameters and may not be generic.

## Why it fires
Checked by the capture-safety scan of semantic analysis, which validates every `parallel.*` closure before walking its body (`src/sema/src/checks/stmt/parallel_check.cpp`; mirrored by the back end in `src/codegen/src/emit/misc/parallel.cpp`). The diagnostic reports `a parallel.* closure cannot be async: parallel.* is synchronous and its pool threads have no event loop, so an await inside the closure would never be driven`, `a parallel.run() closure cannot be generic: the call site has no argument to infer its type parameters from`, or `a parallel.run() closure takes no parameters: the call runs each closure with no arguments`.

## Minimal reproducer
```ts
// fails with CP3912
import console from "std/console";
let results = parallel.run(async () => 1);
console.log(`${results[0]}`);
```
The legal form passes synchronous closures with no parameters (or exactly one `(i: number)` for `parallel.for`, `(acc, i)` for `parallel.reduce`). Pinned by `tests/cases/concurrency/parallel/run/async/parallel_run_async_closure`, `parallel_run_closure_parameter` and `parallel_for_async_closure_error`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Make the closure synchronous — `parallel.*` is synchronous by contract; do work directly, not across an `await`.
2. For `parallel.run`, drop all parameters and type parameters from the closure (it is called with no arguments).
3. If you need async work in parallel, restructure: do the async work first, collect the values, then fan out the synchronous compute; or use workers.
