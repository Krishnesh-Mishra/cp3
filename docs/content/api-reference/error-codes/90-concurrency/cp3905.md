# CP3905 — Worker entry is missing its annotation

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kWorkerMissingAnnotation`

## What it means
A worker — inline or file-based — has no entry arrow whose single parameter is annotated `thread: Thread<In, Out>`. The annotation is the single source of truth for the worker's channel, and without it the compiler cannot know the channel at all.

## Why it fires
Reported when the worker is resolved, at the `new Worker(...)` site or at the worker unit's entry: the pre-scan for the inline form (`src/codegen/src/emit/worker/worker_scan.cpp`, message `an inline worker entry must annotate its parameter as \`thread: Thread<In, Out>\`; the annotation is the single source of truth for the worker's channel`), the worker-unit resolution (`src/codegen/src/emit/worker/worker_module.cpp`), and the toolchain's worker-module loader (a file worker without a default-export arrow or with a wrongly annotated one, message `the worker module '<literal>' must default-export an arrow whose single parameter is \`thread: Thread<In, Out>\``).

## Minimal reproducer
```ts
// fails with CP3905
const w = new Worker((thread) => {
  thread.on("message", (data) => {
    thread.postMessage(data);
  });
});
w.terminate();
```
The legal form annotates the parameter: `new Worker((thread: Thread<number, number>) => { ... })` — the file form defaults to a module whose `export default` is the annotated arrow. Pinned by `tests/cases/concurrency/worker/inline/worker_inline_missing_annotation`, `worker_missing_annotation_file`, `worker_no_default_export` and `worker_check_incorrect_annotation`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Annotate the entry parameter: `(thread: Thread<In, Out>)` with the concrete channel types (e.g. `Thread<number, number>`).
2. If the file form is intended, make the worker module `export default` an annotated arrow (`export default (thread: Thread<number, number>) => { ... };`).
3. If the parameter is rest/destructured or the annotation is missing on one parameter of a multi-parameter arrow, make it a single plain name with the `Thread<...>` annotation.
