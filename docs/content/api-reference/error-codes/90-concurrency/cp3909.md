# CP3909 — Worker captures enclosing state

**Stage:** semantic analysis — concurrency · **Const:** `diagcode::kWorkerEnclosingCapture`

## What it means
An inline worker (`new Worker((thread) => ...)`) references a binding of the enclosing unit — a local of the enclosing function or a module variable of the entry unit. The inline worker has its own module state, so the reference would dangle.

## Why it fires
Reported by the inline-worker pre-scan of codegen (`src/codegen/src/emit/worker/worker_scan.cpp`): an identifier inside the inline arrow that names an enclosing module variable is reported as `'<name>' is module state of the enclosing unit; an inline worker has its own module state (declare it inside the worker or send it as a message)`. Locals declared inside the arrow are fine; top-level functions, imports, builtins and types stay visible (they are code, not state).

## Minimal reproducer
```ts
// fails with CP3909
const base = 10;
const w = new Worker((thread: Thread<number, number>) => {
  thread.on("message", (data) => {
    thread.postMessage(data + base);
  });
});
w.terminate();
```
The legal form declares the value inside the worker (`const base = 10;` inside the arrow) or passes it as a message. Pinned by `tests/cases/concurrency/worker/inline/worker_inline_enclosing_local`.

## What happens
Compilation stops; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Move the value inside the worker arrow (it becomes the worker's own module state).
2. Send the value across as a message — the channel is the sanctioned channel between the two sides.
3. If the value is a constant, duplicate it inside the arrow or make it a parameter of the channel payload.
