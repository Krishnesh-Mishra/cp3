# CP3603 — Native import unsupported

**Stage:** semantic analysis — modules · **Const:** `diagcode::kNativeImportUnsupported`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for a target or configuration that does not support the native-interop import form (`import native "id" as alias`) at all — as opposed to a binding that exists but is missing or broken.

## Why it fires
Never, in this tree: `diagcode::kNativeImportUnsupported` is declared in the code table but has no emission site anywhere in `src/` or `tests/`. The native-import surface is validated when the import is resolved (a missing, stale or malformed binding reports CP3606–CP3608) and again when native calls are type-checked (CP3609/CP3610); no "unsupported" path exists today. The `import native` grammar itself is accepted.

## Minimal reproducer
```ts
// shape — reserved code; nothing fails with CP3603 in this build
import native "some-sdk" as sdk;
console.log(sdk.version());
```
The canonical situation is a build where the native-interop surface is not available for the target platform or SDK, so the import cannot be lowered. No conformance fixture pins CP3603, and none of the native fixtures (e.g. `tests/cli/cases/pkg/native-import.json`) exercise this code.

## What happens
Nothing — the code is never emitted. A native import is always checked through the CP3606–CP3610 family in this build.

## How to fix
1. Nothing to fix for CP3603 itself — it is reserved. A failing `import native` today means a binding problem: re-run `cp3 native-install` for your SDK (see CP3606/CP3608).
2. If you need native interop, confirm your SDK and binding are installed and the binding is not stale.
3. If your build genuinely lacks native support, report it; no fallback diagnostic exists.
