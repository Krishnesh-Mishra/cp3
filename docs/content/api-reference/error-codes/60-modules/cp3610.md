# CP3610 — Native argument type

**Stage:** semantic analysis — modules · **Const:** `diagcode::kNativeArgumentType`

## What it means
A call into a native binding passes an argument whose type does not match the parameter type the binding recorded, so the C++ library would receive a value it cannot read.

## Why it fires
Checked in the semantic analysis of native calls: `src/sema/src/checks/type/native_check.cpp` compares each argument against the binding's recorded parameter list and reports `native call '<fn>': argument <pos> has type '<actual>', but parameter '<name>' expects '<expected>'`, plus a conversion hint when the C++ parameter is a `const char*`, a byte pointer plus a length, or a number pointer plus a length. Arity mismatches are reported separately (CP3403).

## Minimal reproducer
```ts
// fails with CP3610
import native "demo" as dm;
import console from "std/console";

console.log(dm.add("two", 3));
```
The legal form passes arguments of the recorded types: `dm.add(2, 3)`. Pinned by `tests/cli/cases/pkg/native-import.json` (`check-rejects-a-wrong-argument`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Fix the argument to the type the binding expects (the message names the expected type and the parameter).
2. For string-like C++ parameters, pass a cp3 `string` (it lowers to the recorded conversion); for byte buffers, check the binding's `byteBuffer`/`numberArray` parameter kinds.
3. If the SDK changed, re-run `cp3 native-install` so the recorded parameter list matches the SDK in use.
