# CP3608 — Native binding is stale

**Stage:** semantic analysis — modules · **Const:** `diagcode::kNativeBindingStale`

## What it means
The binding's `native.json` records a content hash of its `index.cp3`, and the `index.cp3` on disk no longer matches — the binding was edited or partially regenerated behind the compiler's back.

## Why it fires
Reported by the module loader when it reads the binding: after the metadata parses, the recorded `contentHash` (a SHA-256 of the exact `index.cp3` bytes) is compared against the file on disk (`src/common/src/native/native_bindings_read.cpp`). The diagnostic reports `the native binding '<id>' is stale: its index.cp3 no longer matches the contentHash recorded in native.json`, plus the remedy `re-run 'cp3 native-install <sdk> --name <id> --force'`.

## Minimal reproducer
```ts
// fails with CP3608
// .cp3/native/demo/index.cp3 was edited after `cp3 native-install` ran:
import native "demo" as dm;
import console from "std/console";

console.log(dm.add(2, 3));
```
The legal form is a binding whose `index.cp3` matches the hash recorded at generation time. Pinned by `tests/cli/cases/pkg/native-import.json` (`check-rejects-a-stale-binding`, which overwrites `index.cp3` with a single comment line and expects CP3608).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code. The remedy in the message is the fix.

## How to fix
1. Re-run `cp3 native-install <sdk> --name <id> --force` to regenerate the binding and its hash.
2. If you intentionally edited `index.cp3`, regenerate the binding properly (or drop the `contentHash` — a hand-written binding may carry none and is then not checked).
3. If the message persists after `--force`, delete `.cp3/native/<id>` and install again.
