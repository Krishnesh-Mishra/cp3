# CP3601 — Module not found

**Stage:** semantic analysis — modules · **Const:** `diagcode::kModuleNotFound`

## What it means
The compiler could not resolve an import specifier to a module: a file path that does not exist, a `std/...` specifier outside the known surface, a package the resolver cannot find, or a worker file that is missing.

## Why it fires
Reported by the module loader while resolving imports (the local-file path, the `std/` table, the package resolver, and the worker-file lookup in the `new Worker(...)` path). The message names the specifier, e.g. `cannot find module '<specifier>'`, `cannot read module '<specifier>'`, `cannot find package '<specifier>'`, or `cannot find worker module '<literal>'`. `std/events` and `std/log` are reported with their replacement builtins instead of the generic text.

## Minimal reproducer
```ts
// fails with CP3601
import { EventEmitter } from "std/events";
let e = new EventEmitter();
```
The legal form imports only existing modules: `std/events` was removed in favour of the language-builtin `EventEmitter` (no import at all). Pinned by `tests/cases/diagnostics/eventemitter_import_illegal` and `tests/cases/concurrency/worker/check/worker_check_missing_module`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Check the specifier for typos and the correct `std/...` name against [the module guide](../../../language/06-modules-and-errors/01-modules.md); `std/events` (EventEmitter) and `std/log` no longer exist.
2. For relative imports, confirm the file exists and check the extension (`.cp3` is appended when omitted).
3. For packages, confirm the package is installed and resolvable from the project root (a missing package resolver is also reported here).
4. For `new Worker("./x.cp3")`, confirm the path literal names an existing `.cp3` file.

**Guide:** [Modules](../../../language/06-modules-and-errors/01-modules.md)
