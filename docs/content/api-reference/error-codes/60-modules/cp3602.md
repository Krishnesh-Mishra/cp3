# CP3602 — Package not found

**Stage:** semantic analysis — modules · **Const:** `diagcode::kPackageNotFound`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for a package specifier (a non-relative, non-`std/` import such as `"some-package"`) that cannot be resolved to an installed package.

## Why it fires
Never, in this tree: `diagcode::kPackageNotFound` is declared in the code table but has no emission site. Package resolution failures are reported through CP3601 instead — the package resolver reports `cannot find package '<specifier>'` with `diagcode::kModuleNotFound` (see `src/modules/src/support/import_resolver.cpp`). There is no separate package-not-found diagnostic today, and no test pins CP3602.

## Minimal reproducer
```ts
// no diagnostic today — a package that is not installed is reported as CP3601
import { join } from "some-package";
console.log(join("a", "b"));
```
The canonical situation is a bare specifier such as `"some-package"` that no resolver claims. In this build it fails with CP3601 (`cannot find package 'some-package'`), not CP3602.

## What happens
Nothing — the code is never emitted. Package resolution failures surface as CP3601 and stop compilation there.

## How to fix
1. Check that the package is installed and reachable from the project root (the resolver looks relative to the project).
2. Check the specifier for typos, and confirm the package name is not actually a `std/...` module or a relative path.
3. If you expected a distinct package-not-found message, you will see CP3601 today; please report bugs against that behavior.
