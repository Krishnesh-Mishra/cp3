# CP3606 — Native binding not found

**Stage:** semantic analysis — modules · **Const:** `diagcode::kNativeBindingNotFound`

## What it means
An `import native "id" as alias` names a binding that does not exist: no `<project>/.cp3/native/<id>/native.json` was found (or the id is not a plain name — it may not contain a path separator).

## Why it fires
Reported by the module loader when it resolves the import against the native bindings the project installed (`src/modules/src/support/native_import.cpp`). The diagnostic reports `no native binding '<id>' at '<dir>'` with the remedy `run 'cp3 native-install <sdk> --name <id>' to create it` as part of the message; an id containing `/`, `\` or `:` is rejected the same way before any file is read.

## Minimal reproducer
```ts
// fails with CP3606
import native "nope" as dm;
import console from "std/console";

console.log(dm.add(2, 3));
```
The legal form installs the binding first (`cp3 native-install <sdk> --name nope`) so `.cp3/native/nope/native.json` exists, then imports it. Pinned by `tests/cli/cases/pkg/native-import.json` (`check-rejects-an-unknown-binding`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Run `cp3 native-install <sdk> --name <id>` for the SDK and id in your import.
2. Confirm the id is a plain name (no path separators) and matches a folder under `.cp3/native/`.
3. If the binding was installed, check the project root — the loader resolves `<project>/.cp3/native/<id>`, and a stale or half-written install is what CP3608 is for.
