# CP3605 — Prelude error

**Stage:** semantic analysis — modules · **Const:** `diagcode::kPreludeError`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for a failure to read a prelude file — a per-folder source fragment that would be spliced into every unit that imports it (the prelude proposal). The feature is parked in v0.2.

## Why it fires
Not in this build: the only emission site is the module loader's prelude path (`src/modules/src/support/unit_loader.cpp`, reporting `cannot read prelude file '<path>'`), and that path is disabled behind a compile-time switch. The prelude scanner and injector stay in the tree for a future release, but no unit receives an injected prelude, so no prelude can be missing at runtime.

## Minimal reproducer
```ts
// shape — no user-facing reproducer exists in this build
// (prelude injection is disabled; the situation only existed when
//  the prelude design was enabled)
```
The canonical situation is a prelude ref in a folder's `.cp3/prelude` configuration that names a file the loader cannot read. No conformance fixture pins CP3605, and no user program can produce it today.

## What happens
Nothing — the code cannot fire in this build.

## How to fix
1. Nothing to fix — CP3605 is parked with the prelude feature.
2. If a future build enables preludes and this fires, fix the prelude path named in the message: the file must exist and be readable as a cp3 source file.
3. If you want ambient declarations today, use imports or the language's builtin surface instead.
