# CP3609 — Unknown native binding member

**Stage:** semantic analysis — modules · **Const:** `diagcode::kNativeUnknownMember`

## What it means
A call `alias.<name>(...)` (or a member read) names a member that the binding's `native.json` does not declare — the function, class or enum simply is not there.

## Why it fires
Checked in the semantic analysis of native calls, after the module loader parked the binding in the module graph: `src/sema/src/checks/type/native_check.cpp` looks the member up in the binding and reports `the native binding '<id>' has no declaration named '<name>'` when nothing matches.

## Minimal reproducer
```ts
// fails with CP3609
import native "demo" as dm;
import console from "std/console";

console.log(dm.nope(2, 3));
```
The legal form calls a member the binding actually declares (see the binding's `native.json` or the SDK's generated `index.cp3`). Pinned by `tests/cli/cases/pkg/native-import.json` (`check-rejects-an-unknown-member`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Check the member name against the binding's declarations (`native.json` functions/classes/enums) — the message names what you asked for.
2. Re-run `cp3 native-install` with the SDK version that declares the member you want; bindings are generated per SDK.
3. If the SDK declares the member as a constant or a type rather than a function, adjust the call shape to what the binding records.
