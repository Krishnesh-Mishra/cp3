# CP3703 — Multiple inheritance

**Stage:** semantic analysis — classes · **Const:** `diagcode::kMultipleInheritance`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for a class with more than one direct base class. The v0.2 object model is single-inheritance for classes.

## Why it fires
Never, in this tree: `diagcode::kMultipleInheritance` is declared in the code table but has no emission site anywhere in `src/` or `tests/`. Class grammar admits exactly one `extends` clause for a class (`src/parser/src/decl/declarations.cpp`) — `class C extends A, B { }` is not parseable as a class at all and fails in the parser, not in semantic analysis. Interfaces are the exception: an interface may name multiple base `extends` types, which is supported.

## Minimal reproducer
```ts
// what CP3703 would own — rejected today by the parser, not with CP3703
class A { }
class B { }
// class C extends A, B { }   // not valid: a class has one extends clause

// legal: single inheritance + interface conformance
class C extends A { }
```
The canonical situation is `extends A, B` on a class. No conformance fixture pins CP3703, and none can until a class-inheritance grammar with more than one base exists.

## What happens
Nothing — the code is never emitted. A class that tries `extends A, B` is rejected at parse time as a syntax error before class analysis runs.

## How to fix
1. Use single inheritance: pick one base class and compose the rest.
2. Factor the shared contract into an interface and implement it alongside one base class.
3. For behavior sharing, use a helper class composed as a field, not a second base.
