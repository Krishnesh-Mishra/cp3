# CP3708 — Computed member name

**Stage:** semantic analysis — classes · **Const:** `diagcode::kComputedMemberName`

## What it means
A class member's name is computed (`[expr] = ...`, `[expr]() { ... }`) and the key is not a literal. A cp3 class has a fixed member set, so a member whose name is only known at runtime cannot exist.

## Why it fires
Checked when the class model is collected in semantic analysis (and repeated by the back end when the same model is built for codegen). Only a literal key — a string or number literal — is accepted; anything else reports `a computed class member name must be a literal: a cp3 class has a fixed set of members`. See `src/sema/src/checks/class/class_check.cpp` (properties, methods, accessors) and `src/codegen/src/support/class/class_collect.cpp`.

## Minimal reproducer
```ts
// fails with CP3708
import console from "std/console";
const key = "x";
class C { [key] = 1; }
const c = new C();
console.log("unreachable");
```
The legal form names the member directly, or uses a literal key: `class C { "x" = 1; }` (a literal is exactly a string/number literal key). Pinned by `tests/cases/classes/01/computed/computed_member_name_error`.

## What happens
Compilation stops at the front end (or the back end when repeated there); nothing is emitted; the diagnostic carries the code.

## How to fix
1. Use a plain member name, or quote a literal key (`"x"`) directly in the class body.
2. If the member genuinely needs a dynamic name, use a `Map<K, V>` field instead of a fixed member set.
3. If the key is a constant you control, inline its value as a literal — the check is about compile-time knowledge, not about constants.
