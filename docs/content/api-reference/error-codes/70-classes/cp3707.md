# CP3707 — Generic local method

**Stage:** semantic analysis — classes · **Const:** `diagcode::kGenericLocalMethod`

## What it means
A generic method (or a static initializer block) belongs to a class declared inside a function. The class lowers to a C++ local class, which cannot have member templates — so the generic member has no legal lowering.

## Why it fires
Reported by the back end in the class-collection pass (`src/codegen/src/support/class/class_collect.cpp`), which models classes for native codegen. Two forms report this code: a static initialization block in a function-local class (`a static initialization block in a function-local class is not supported`), and a generic method of a function-local class (`a generic method of a function-local class is not supported: C++ has no member template in a local class`).

## Minimal reproducer
```ts
// fails with CP3707
import console from "std/console";

function f(): number {
  class C {
    function identity<T>(x: T): T { return x; }
  }
  const c = new C();
  return c.identity(1);
}

console.log(f());
```
The legal form declares the class at module scope (`class C { function identity<T>(x: T): T { return x; } }`), or drops the generic parameter from the local method. Pinned by `tests/cases/generics/01/generic/generic_method_local_class_error`.

## What happens
Compilation stops at the back end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Hoist the class out of the function to module (or namespace) scope.
2. If the method does not need to be generic, drop the type parameter (e.g. write `function identity(x: number): number`).
3. If the local class only needs one instantiation, use a single concrete signature.
