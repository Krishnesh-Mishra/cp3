# CP3704 — Invalid override

**Stage:** semantic analysis — classes · **Const:** `diagcode::kInvalidOverride`

**Reserved / not currently emitted by the compiler.**

## What it means
The code slot is reserved for an `override` member whose relationship to the base class is invalid — for example, an `override` with no base member of the same name, or a signature that does not match the member it replaces.

## Why it fires
Never, in this tree: `diagcode::kInvalidOverride` is declared in the code table but has no emission site anywhere in `src/` or `tests/`. The `override` checks that exist today report different codes: an `override` with no matching base member reports CP3305 (`member '<name>' is marked override but base class '<base>' has no such member`), and an override of a different member kind reports CP3401 (`member '<name>' cannot override a member of a different kind`) — see `src/sema/src/checks/class/class_check.cpp` (`checkClassHierarchy`).

## Minimal reproducer
```ts
// what CP3704 would own — reported today as CP3305 / CP3401
class Base {
  function f(x: number): number { return x; }
}
class Derived extends Base {
  override function g(x: number): number { return x; }  // CP3305: nothing to override
}
```
The canonical situation is an `override` that does not correspond to a base-class member. No conformance fixture pins CP3704 in this tree.

## What happens
Nothing — the code is never emitted. An invalid `override` today fails with CP3305 (member not found) or CP3401 (type mismatch) and stops compilation.

## How to fix
1. Match the member to the base exactly: same name, and the same kind (method vs. property) as the base member.
2. If there is no base member to override, drop `override` — or add the member to the base.
3. If the base member moved, re-sync: the base's name, kind and signature must match what you wrote.
