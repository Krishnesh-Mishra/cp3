# CP3705 — Duplicate member

**Stage:** semantic analysis — classes · **Const:** `diagcode::kDuplicateMember`

## What it means
A class ends up with two members of the same name, which cannot be distinguished at call sites.

## Why it fires
Checked in the class-collection pass of semantic analysis (`src/sema/src/checks/class/class_check.cpp`): a constructor parameter property whose name already exists on the class reports `duplicate class member '<name>'`. Parameter properties desugar to field declarations, so a `constructor(private x: number)` against an existing `x` member is a duplicate.

## Minimal reproducer
```ts
// fails with CP3705
class Counter {
  count: number = 0;
  constructor(private count: number) { }
}
```
The legal form names the parameter property differently from the existing member, or drops the parameter property and assigns explicitly. No conformance fixture pins CP3705 in this tree; the shape follows the parameter-property collection in `class_check.cpp`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Rename the parameter property (or the field) so the two members are distinct.
2. If you want the parameter to seed the existing field, drop `private` and assign `this.count = count;` in the constructor body.
3. If you duplicated a method by copy-paste, remove one of the pair.
