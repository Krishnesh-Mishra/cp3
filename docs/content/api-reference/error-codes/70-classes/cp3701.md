# CP3701 — Missing interface member

**Stage:** semantic analysis — classes · **Const:** `diagcode::kMissingInterfaceMember`

## What it means
A class is required to provide a member it does not provide — an abstract member inherited from an abstract base, or a required member of the shape it is being assigned against.

## Why it fires
Checked at the end of class analysis in semantic analysis: a concrete class must implement every abstract member of its bases (`src/sema/src/checks/class/class_conform_check.cpp`, message `class '<name>' must implement abstract member '<member>'`), and a class assigned to a structural shape must carry every required field (`missing required member '<member>' in class '<name>'`). Note the `implements` clause on the class declaration itself is self-documenting in this version; the error fires where the value is used (or on the concrete subclass), not at the clause.

## Minimal reproducer
```ts
// fails with CP3701
abstract class Shape { abstract function area(): number; }
class Circle extends Shape { }
```
The legal form implements the abstract member: `class Circle extends Shape { function area(): number { return 3.14; } }` (or declares `abstract class Circle extends Shape { }`). Pinned by `tests/cases/classes/01/abstract/abstract_subclass_missing_impl_error` (placeholder code, `contains: "area"`).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Add the missing member to the class (a method matching the abstract signature, or the required field on the class).
2. If the class should remain abstract, write `abstract class Circle extends Shape { }`.
3. If you are assigning a class value to a narrower shape, widen the shape or add the required member to the class.
