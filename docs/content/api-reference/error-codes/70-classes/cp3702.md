# CP3702 — Private field in a literal

**Stage:** semantic analysis — classes · **Const:** `diagcode::kPrivateFieldInLiteral`

## What it means
An object literal is being used as a value of a class type, but the literal cannot see the class's private or protected members. A class instance's private state is only settable through the class itself.

## Why it fires
Checked in semantic analysis when an object literal is checked against a class shape (`src/sema/src/checks/class/class_conform_check.cpp`): every member of the class that is private or protected must be accounted for by the literal, and a literal cannot satisfy it. The diagnostic reports `object literal cannot satisfy class '<name>': field '<field>' is private` (or `protected`).

## Minimal reproducer
```ts
// fails with CP3702
class P { private name: string = "a"; }
let x: P = { name: "b" };
```
The legal form constructs the class (`let x = new P();`) — the private field is then set inside the class. Pinned by `tests/cases/classes/02/object/object_literal_private_error` (placeholder code, `contains` the member).

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Build the value through the class: `const p = new P();` instead of a literal.
2. If the literal is meant to be a plain data shape, type it as an object type, not the class (`let x: { name: string } = { name: "b" };`).
3. If the field should be set from outside, make it public — private should mean private.
