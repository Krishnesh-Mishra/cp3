# CP3709 — Uninitialized field

**Stage:** semantic analysis — classes · **Const:** `diagcode::kUninitializedField`

## What it means
A class field has neither an initializer nor a definite-assignment mark (`!:`), and no constructor assigns it — so an instance could carry an unreadable field.

## Why it fires
Checked at the end of class analysis in semantic analysis (`src/sema/src/checks/class/class_check.cpp`, `checkDefiniteAssignment`): for each field without an initializer, the analysis looks at what every constructor assigns and what `!:` declares. A field that is never assigned anywhere reports `field '<name>' is declared without an initializer and is never assigned in a constructor; give it an initial value or mark it '!:' when initialization happens elsewhere`.

## Minimal reproducer
```ts
// fails with CP3709
class C {
  f: number;
  constructor() { }
}
const c = new C();
```
The legal form gives the field an initial value (`f: number = 0;`), assigns it in a constructor (`this.f = 0;`), or marks it definite-assignment (`f!: number;`) when it is set elsewhere. Pinned by `tests/cases/v0-2-2/uninitialized_field_error` and `tests/cases/memory-weak/_ambiguous/uninitialized/uninitialized_field_type`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Add an initial value at the declaration: `f: number = 0;`.
2. Assign the field in every constructor path: `constructor() { this.f = 0; }`.
3. If initialization happens elsewhere (framework, `init()`, deserializing), mark it definite-assignment: `f!: number;`.
