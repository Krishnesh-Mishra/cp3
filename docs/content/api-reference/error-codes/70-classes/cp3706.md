# CP3706 — Mixed enum backing

**Stage:** semantic analysis — classes · **Const:** `diagcode::kMixedEnumBacking`

## What it means
An enum mixes number-backed and string-backed members. A cp3 enum is backed by one kind only; mixing them makes the enum's representation and ordering ambiguous.

## Why it fires
Checked in the enum-collection pass of semantic analysis (`src/sema/src/checks/type/enum_check.cpp`): as each member's initializer is read, the check records whether it saw a string member and whether it saw a number member. If both are seen, the diagnostic reports `enum '<name>' mixes number and string members; an enum must be backed by one kind only`.

## Minimal reproducer
```ts
// fails with CP3706
import console from "std/console";
enum Mixed { A = 1, B = "b" }
console.log(Mixed.A);
```
The legal form keeps one backing kind: `enum Numbers { A = 1, B = 2 }` or `enum Strings { A = "a", B = "b" }`. Pinned by `tests/cases/enums/01/mixed/mixed_backing`.

## What happens
Compilation stops at the front end; nothing is emitted; the diagnostic carries the code.

## How to fix
1. Make the enum all-number or all-string: change the odd-one-out member to match its siblings.
2. If you need both, split into two enums — one for each backing kind — and convert at the boundary.
3. If you want auto-incremented numbers, leave the numeric members without initializers entirely.
