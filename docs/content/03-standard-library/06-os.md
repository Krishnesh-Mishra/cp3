# Operating system information

`std/os` exposes host information through a default namespace import:

```ts
import os from "std/os";
```

The module reports information about the machine and user environment. Values can differ between the time the program is built and the time it runs because they describe the runtime host.

## Platform and host names

- `os.platform()` returns `"windows"`, `"macos"`, or `"linux"`.
- `os.hostname()` returns the machine's host name.
- `os.homedir()` returns the current user's home directory.
- `os.tmpdir()` returns the system temporary directory.

Use `path.join` to create paths below the returned home or temporary directory. Do not assume that the home directory or temp directory is writable; handle filesystem errors.

## CPU and memory

- `os.cpus()` reports the number of logical CPU cores.
- `os.totalMemory()` reports total system memory in bytes.
- `os.freeMemory()` reports currently free system memory in bytes.

The memory readings are snapshots and may change immediately. They are useful for diagnostics and rough resource decisions, not for reserving memory safely or guaranteeing that an allocation will succeed.

## Example

```ts
console.log("platform", os.platform());
console.log("host", os.hostname());
console.log("logical CPUs", os.cpus());
console.log("free bytes", os.freeMemory());
```

The console namespace is described in [Console](01-console.md).

## API summary

| Member | Return type | Description |
| --- | --- | --- |
| `platform()` | `string` | Platform name |
| `hostname()` | `string` | Machine host name |
| `homedir()` | `string` | Current user's home directory |
| `tmpdir()` | `string` | System temporary directory |
| `cpus()` | `number` | Logical CPU count |
| `totalMemory()` | `number` | Total memory in bytes |
| `freeMemory()` | `number` | Free memory in bytes |

These are the supported `std/os` members. They are not a full Node `os` compatibility layer.

## Signatures and units

| Call | Result | What the result means |
| --- | --- | --- |
| `platform()` | `string` | One of `windows`, `macos`, `linux` |
| `hostname()` | `string` | Host machine name |
| `homedir()` | `string` | Current user's home-directory path |
| `tmpdir()` | `string` | Host temporary-directory path |
| `cpus()` | `number` | Logical CPU count, not a guaranteed CPU quota |
| `totalMemory()` | `number` | Total physical system memory in bytes |
| `freeMemory()` | `number` | A runtime snapshot of free system memory in bytes |

The namespace is closed to these seven members. This API reports basic host facts; it does not provide CPU model, per-process memory use, load averages, network interfaces, or the complete Node `os` surface.

## Host information is runtime state

These calls describe the machine that runs the executable, not necessarily the machine that compiled it. A binary built on one host can report different values on another. Cache such values only when the application intends a startup snapshot; CPU and memory availability can change during execution.

A logical CPU count is not a promise that the process may use every reported thread. Containers, job schedulers, affinity masks, and OS policy can limit effective parallelism. Use the CP3 concurrency API and measured workload behavior to choose work partitioning instead of treating `cpus()` as a scheduling guarantee.

## Paths and permissions

`homedir()` and `tmpdir()` return paths, not open directories or permission grants. Compose child paths with `std/path`, then handle `std/fs` failures. A temporary path may be cleaned up by the operating system or collide with another process if the program assumes a fixed filename; create unique names and clean up resources explicitly.

`hostname()` is useful for diagnostics but should not be treated as an authenticated machine identity. It can be changed and may not be unique in a deployment.

## Test and implementation boundary

The conformance cases under `tests/cases/stdlib/02/os` check supported platform strings and basic non-negative/positive memory readings. Tests cannot make host-specific values stable. The implementation and semantic member table are under `src/std/os`; unknown members are compile-time errors rather than dynamic property access.
