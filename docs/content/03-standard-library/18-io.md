# I/O readiness

`std/io` exposes the reactor primitives for native libraries that already have a socket and a non-blocking step API. It does not make a blocking C call concurrent.

```ts
import io from "std/io";
```

## `waitReadable` and `waitWritable`

```ts
await io.waitReadable(fd); // Promise<void>
await io.waitWritable(fd); // Promise<void>
```

`fd` is a native socket descriptor: an `int` on POSIX, or the `SOCKET` value exposed by the native library on Windows. Keep it in the exact-integer range of `number`.

The wait suspends only the calling async function. Timers, promise continuations and other fd waiters continue on the same event loop. Many waiters can share a descriptor, including one reader and one writer.

The promise rejects when the poll reports an error, the peer hangs up or disconnects, the descriptor is invalid, or the descriptor is closed while the wait is registered. One shared 100 ms descriptor-validity check covers every pending wait (never one timer or thread per descriptor); a local close is reported on the next check. Phase 1 has no cancellation token; a pending waiter stays pending until it settles or fails.

## `pollUntilDone`

```ts
await io.pollUntilDone(
  () => nativeLib.socket(handle),
  () => nativeLib.progress(handle),
);
```

`checkProgress` returns one of:

| Constant | Meaning |
| --- | --- |
| `io.POLL_READING` | Await `waitReadable(getSocket())`. |
| `io.POLL_WRITING` | Await `waitWritable(getSocket())`. |
| `io.POLL_DONE` | Resolve the promise. |
| `io.POLL_FAILED` | Reject the promise. |

`getSocket()` is called again on every iteration, so a connect sequence can move to a new descriptor. An unknown state rejects the promise. The helper is implemented once in the runtime; libraries do not write their own loop.

## Event loop sharing

`std/io` and `std/network` share one libuv loop per thread. The runtime `EventLoop` remains authoritative and drives libuv from its idle phase. Linux uses libuv's epoll backend; Windows uses libuv's IOCP backend. Cross-thread wakeup uses libuv's async handle.

## Blocking libraries

A pure blocking C library with no pollable fd belongs to the phase 3 offload pool:

```ts
import native async "blocking-lib" as lib;
```

That form is not available yet. It starts only after the phase 1-2 reactor tests pass. Do not wrap a blocking call in `async` as a substitute; it still blocks the loop.
