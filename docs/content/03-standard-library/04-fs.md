# File system

`std/fs` provides local file and directory operations. Import the default namespace:

```ts
import fs from "std/fs";
```

The module has synchronous calls and promise-based variants for operations that can take time. Paths are passed as strings; use `std/path` to compose them portably. File-system calls operate with the permissions of the current process.

## Choosing synchronous or asynchronous calls

Use the synchronous form in short startup code or a command that intentionally blocks while doing file work. Use the promise form when the surrounding program is already asynchronous or when a long operation should not block other event-loop work.

```ts
const text = fs.readFileSync("config.json");
const later = await fs.readFile("config.json");
```

Both forms report failures. Synchronous calls throw directly; promise calls reject and should be awaited or handled with `.catch`.

An async call is not automatically faster for one isolated read. Its benefit is that the program can compose the operation with other asynchronous work without blocking the event-loop thread. Keep the sync form when the program deliberately needs an immediate result during startup and blocking is acceptable.

## Reading and writing

The file API includes text reads and writes, binary byte reads and writes, and their promise-based counterparts. Select the text operation when the file is text in the expected encoding; select the byte operation when the content must remain unchanged as bytes.

```ts
const source = await fs.readFile("src/main.cp3");
await fs.writeFile("out.txt", "Build complete\n");
```

Do not treat a text read as a streaming parser for arbitrarily large files. Use the stream helpers when bounded chunks are important.

## Directories and metadata

The surface includes directory creation, removal, listing, existence checks, and file metadata. The `FileStats` result exposes `size`, `isFile`, `isDirectory`, and `modifiedAt`.

```ts
const stats = await fs.stat("data/input.bin");
if (stats.isFile) {
  console.log("bytes:", stats.size);
}
```

`exists` answers a point-in-time question; another process can change the path immediately afterward. For operations that matter, perform the operation itself and handle its error instead of relying on an earlier check.

`stat` describes the entry at the time of the call. `size` is measured in bytes; `modifiedAt` is a CP3 `Date`. The booleans distinguish regular files and directories. A result can become stale if another process changes the path later.

## File streams

`readFileStream(path, chunkSize?)` returns a stream of file bytes in chunks. `writeFileStream(path)` creates a writer for incremental output. Use streams to bound working memory when processing large inputs.

```ts
const reader = fs.readFileStream("large.log", 64 * 1024);
```

The exact stream consumption methods are defined by the runtime stream type; inspect the standard-library member completion for the installed compiler version. Always close or finish a stream according to its supported interface, including error paths.

The stream API avoids requiring the entire file contents as one string, but callers should still process each chunk promptly. A large `chunkSize` trades fewer callbacks for more memory per chunk. Choose a size appropriate to the workload and handle both stream data and completion/error events supported by the stream type.

## Working directory and paths

Relative paths are interpreted from the process working directory. Build paths with `path.join` rather than embedding platform-specific separators. See [Path](05-path.md).

## Errors and safety

Permission denial, missing paths, invalid file types, and device errors can all fail. Catch errors at a boundary where you can add context or recover. Avoid following a check-then-use pattern for security-sensitive paths; the file may change between those two operations.

Never write untrusted filenames into privileged directories without validating the destination. Normalize paths for presentation and comparison, but remember that string normalization does not establish filesystem identity or prevent symlink traversal.

For replacement-style writes that must not leave a partially written destination after a crash, write a temporary file in the same directory and rename it only after the write completes, where the platform's rename guarantees meet the application's needs. The standard library does not promise transactional file operations.

## API inventory

Synchronous methods: `readFileSync`, `writeFileSync`, `appendFileSync`, `existsSync`, `mkdirSync`, `readdirSync`, `statSync`, and `unlinkSync`.

Promise-based methods: `readFile`, `writeFile`, `appendFile`, `mkdir`, `readdir`, `stat`, and `unlink`. Read methods accept an optional encoding string; directory methods return names as `string[]`; stat returns `FileStats`.

Streaming methods: `readFileStream(path, chunkSize?)` returns a `ReadStream`, and `writeFileStream(path)` returns a `WriteStream`. `FileStats` has `size`, `isFile`, `isDirectory`, and `modifiedAt` fields. Stream event details are exposed by the runtime stream interface and editor completion.
