# File system

`std/fs` provides local file and directory operations. Import the default namespace:

```ts
import fs from "std/fs";
```

The module has synchronous calls and promise-based variants for operations that can take time. Paths are passed as strings; use `std/path` to compose them portably. File-system calls operate with the permissions of the current process.

## Choosing synchronous or asynchronous calls

Use the synchronous form in short startup code or a command that intentionally blocks while doing file work. Use the promise form when the surrounding program is already asynchronous or when a long operation should not block other event-loop work.

```ts
const text = fs.readFileSync("config.json");
const later = await fs.readFile("config.json");
```

Both forms report failures. Synchronous calls throw directly; promise calls reject and should be awaited or handled with `.catch`.

An async call is not automatically faster for one isolated read. Its benefit is that the program can compose the operation with other asynchronous work without blocking the event-loop thread. Keep the sync form when the program deliberately needs an immediate result during startup and blocking is acceptable.

## Reading and writing

The file API includes whole-file reads and writes as CP3 strings, with synchronous and promise-based counterparts. `readFile`/`readFileSync` always return `string`; the optional `encoding` argument is accepted and ignored (UTF-8 is the only meaningful value for a CP3 string), and there is no `Buffer`-returning read call — `writeFile`/`appendFile` likewise take `data: string`. For true byte-oriented I/O, use `readFileStream` (its `"data"` chunks are nominal `Buffer` values) and `writeFileStream` (whose `write` accepts `string` or `Buffer`); see [File streams](#file-streams). Select the text operation when the file is text; use the streams when the content must remain unchanged as bytes.

```ts
const source = await fs.readFile("src/main.cp3");
await fs.writeFile("out.txt", "Build complete\n");
```

Do not treat a text read as a streaming parser for arbitrarily large files. Use the stream helpers when bounded chunks are important.

## Directories and metadata

The surface includes directory creation (`mkdir`), listing (`readdir`), existence checks, file removal, and file metadata. There is no `rmdir`/`rm` member: `unlink`/`unlinkSync` remove files only, and a directory cannot be removed through `std/fs`. The `FileStats` result exposes `size`, `isFile`, `isDirectory`, and `modifiedAt`.

```ts
const stats = await fs.stat("data/input.bin");
if (stats.isFile) {
  console.log("bytes:", stats.size);
}
```

`exists` answers a point-in-time question; another process can change the path immediately afterward. For operations that matter, perform the operation itself and handle its error instead of relying on an earlier check.

`stat` describes the entry at the time of the call. `size` is measured in bytes; `modifiedAt` is a CP3 `Date`. The booleans distinguish regular files and directories. A result can become stale if another process changes the path later. In a `rust` or `cpp` project, `size` is the exact `u64` byte count (`usize` where a count is requested); a `typescript` project keeps `number`, matching the standard-library width table. The `readFileStream` chunk size uses the same file-size width.

## File streams

`readFileStream(path, chunkSize?)` returns a `ReadStream` that yields file bytes in chunks (the default chunk size is 64 KiB when `chunkSize` is omitted or `0`). `writeFileStream(path)` returns a `WriteStream` for incremental output. Use streams to bound working memory when processing large inputs, and when the content must remain bytes rather than text:

```ts
const reader = fs.readFileStream("large.log", 64 * 1024);
reader.on("data", (chunk: Buffer): undefined => {
  // chunk is a std/buffer Buffer with the file bytes
  return undefined;
});
reader.on("end", (): undefined => undefined);
reader.on("error", (message: string): undefined => undefined);
```

| Receiver | Member | Signature | Meaning |
| --- | --- | --- | --- |
| `ReadStream` | `on("data", listener)` | `(chunk: Buffer) => void` | A chunk of file bytes. The pump starts at the first `on` registration and posts one read per microtask; keep the event loop driven. |
| `ReadStream` | `on("end", listener)` | `() => void` | The file reached EOF. |
| `ReadStream` | `on("error", listener)` | `(message: string) => void` | The read failed; with no `"error"` listener the pump throws from its microtask, which terminates the program. |
| `WriteStream` | `write(chunk)` | `(chunk: string \| Buffer) => void` | Appends bytes; the destination is opened (truncated) lazily at the first write/`end`. |
| `WriteStream` | `end()` | `() => void` | Closes the file. |
| `WriteStream` | `on("error", listener)` | `(message: string) => void` | The open/write failed; with no listener a failure throws from the call site. |

Always handle or avoid open/write failures on the error path. A large `chunkSize` trades fewer callbacks for more memory per chunk.

## Working directory and paths

Relative paths are interpreted from the process working directory. Build paths with `path.join` rather than embedding platform-specific separators. See [Path](05-path.md).

## Errors and safety

Permission denial, missing paths, invalid file types, and device errors can all fail. Catch errors at a boundary where you can add context or recover. Avoid following a check-then-use pattern for security-sensitive paths; the file may change between those two operations.

Never write untrusted filenames into privileged directories without validating the destination. Normalize paths for presentation and comparison, but remember that string normalization does not establish filesystem identity or prevent symlink traversal.

For replacement-style writes that must not leave a partially written destination after a crash, write a temporary file in the same directory and rename it only after the write completes, where the platform's rename guarantees meet the application's needs. The standard library does not promise transactional file operations.

## API inventory

Synchronous methods: `readFileSync`, `writeFileSync`, `appendFileSync`, `existsSync`, `mkdirSync`, `readdirSync`, `statSync`, and `unlinkSync`.

Promise-based methods: `readFile`, `writeFile`, `appendFile`, `mkdir`, `readdir`, `stat`, and `unlink`. Read methods accept an optional encoding string (accepted but ignored — contents are always returned as `string`); directory methods return names as `string[]`; stat returns `FileStats`.

There is no `rmdir`, `rm`, `rename`, or `unlink` for directories, and no `Buffer`-returning whole-file read; the closed member table has no such members. `unlink`/`unlinkSync` remove files only.

Streaming methods: `readFileStream(path, chunkSize?)` returns a `ReadStream` whose `"data"` chunks are nominal `Buffer` values, and `writeFileStream(path)` returns a `WriteStream` whose `write` accepts `string | Buffer`. `FileStats` has `size`, `isFile`, `isDirectory`, and `modifiedAt` fields.

Watching: `watch(path, callback)` watches a file or directory and calls `callback(eventType, filename)` on every change (`eventType` is `"change"` or `"rename"`); it returns an `FsWatcher` whose `close()` stops delivery and keeps the program alive until then.
